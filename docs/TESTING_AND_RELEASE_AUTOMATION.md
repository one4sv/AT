# Проверка версий и регрессионные тесты

## Версии

Запуск: `node scripts/check-release.mjs`.

Проверяет совпадение версии из `package.json` с `roadmapCurrent`, уникальность записей, наличие версии в ключевых MD, ссылку на roadmap на странице About и английские неизменяемые названия версий.

**Не генерирует релизы из коммитов.** Записи истории и описания остаются ручными: один коммит не означает один релиз. Даты коммитов не равны подтверждённым датам выпуска. При подготовке версии сначала согласовать содержимое, затем изменить roadmap и документацию и запустить проверку.

## Playwright

E2E-тесты находятся в `tests/e2e` и имеют отдельный `package.json`, чтобы не менять основную зависимость приложения и `package-lock.json` до настройки CI.

```bash
npm install --prefix tests/e2e
npx --prefix tests/e2e playwright install chromium
npm run dev
# в другой консоли:
npm run test --prefix tests/e2e
```

Для авторизованных тестов нужен отдельный тестовый аккаунт: сохранить состояние браузера в локальном файле и задать `AT_E2E_STORAGE_STATE`. Не коммитить cookies, токены и скриншоты пользовательских данных. `AT_E2E_BASE_URL` по умолчанию `http://127.0.0.1:5173`. Проверки, требующие авторизации, пропускаются при отсутствии этого файла, а не помечаются успешными.

Критические сценарии: Acc (клик по содержимому не закрывает Info; сворачивание только в начале прокрутки), переключение языка, модальное окно ShareAcc, календарь в 7 колонок и сброс позиции **до paint**, статистика, модалки, непрерывность кадров японских WebP, desktop wheel каталога и отсутствие влияния `settings_layout` на телефон. Для динамических экранов предпочтительны устойчивые `data-testid` и тестовые фикстуры; визуальные снапшоты нужно утверждать отдельно на desktop и iPhone Safari/WebKit. Скриншоты и ручная проверка обязательны прежде, чем объявлять устранение регрессии доказанным.

## Инвариант названий roadmap

Имена версий, включая `0.0 The Beginning`, должны быть неизменными английскими строками. `0.0` имеет дату . У версии `0.1` название `The Foundation`, у `0.6.2` — `The New Palette`, у `0.7` — `The Castle`. При RU/EN переключении переводятся лишь описания, не имена. Проверять это в E2E.


## Реестр текущих регрессий интерфейса

[SLIDERS.md](SLIDERS.md) содержит 16 механизмов и исходники. Тесты в `tests/e2e/appearance.spec.ts` проверяют непрерывность кадра в Wallpaper Studio и поведение wheel, а `tests/e2e/smoke.spec.ts` содержит контроль центрирования календаря. Большая часть авторизованных тестов зависит от фикстуры `AT_E2E_STORAGE_STATE`; **пропуск — не успех**. Для мобильных жестов необходим отдельный WebKit/реальный iPhone.

## CI: сборка и публичные smoke-тесты 

Файл `.github/workflows/client-ci.yml` запускается при push в `main`, pull request и вручную. Он выполняет `npm run check:release`, `npm run build`, затем публичные Playwright smoke-тесты в Chromium. Тест переключения RU/EN проверяет перевод заголовка roadmap и сохранение английских названий версий.

CI не получает пользовательские cookies или тестовую базу. Сценарии Acc, активности, статистики и календаря с авторизацией в `tests/e2e/smoke.spec.ts` остаются **пропущенными**, пока не настроен изолированный `AT_E2E_STORAGE_STATE` и `AT_E2E_HABIT_ID`. В том числе тест заголовков статистики на RU/EN требует fixture с данными. Пропуск не равен подтверждению успешного E2E.

Для локального авторизованного прогона сначала запустить Vite, затем `AT_E2E_STORAGE_STATE=... AT_E2E_HABIT_ID=... npm run test --prefix tests/e2e -- --project=chromium-desktop smoke.spec.ts`. Дополнительно вручную проверить iPhone Safari: Chromium не заменяет WebKit и реальные жесты.

## Воспроизводимая установка Tiptap 

Первый запуск CI обнаружил TS2769 в `src/pages/Post/PostEditor.tsx`: при установке без lockfile npm создавал вторую копию `@tiptap/core` внутри `@tiptap/starter-kit`, несовместимую с типами корневой копии. `package.json` теперь содержит npm `overrides["@tiptap/core"] = "$@tiptap/core"`, чтобы все расширения использовали ту же версию, что и редактор. Не скрывать проблему приведением типов к `any`. Проверить новый CI после установки.

## Загрузка страниц и модалок по требованию 

Маршруты и модули `Blackout` разделены по чанкам через `React.lazy`/`Suspense`. Проверять первый JS-файл и публичные маршруты после `npm run build`; подробности — [PERFORMANCE.md](PERFORMANCE.md). Авторизованные модальные сценарии отдельно проверять с фикстурой.

## Функциональная приёмка текущей версии

- Для совместной активности нужны авторизованные E2E: владелец/участник, пара/беседа, принятие/отказ, блокировка, права, личное/общее выполнение, таймер, счётчик, задачи, расписание и дата вступления. Проверить прямые API-попытки обхода `owner` и ограничений даты.
- На ПК и iPhone проверить страницу календаря, длинные поля `TA`/`AutoDesc`, редактор постов и медиа, RU/EN, клавиатуру, жесты, изображения `SectionArt`, предпросмотр фонов, восстановление после ошибки.
- Авторизованные тесты без `AT_E2E_STORAGE_STATE` пропускаются; пропущенный тест не означает успешную проверку. CI и `READY` не доказывают пользовательский E2E.
- Названия версий в roadmap неизменны между локалями; даты ориентиров хранятся исключительно в [CHANGELOG.md](CHANGELOG.md).
