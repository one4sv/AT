# Цели внутри «Планов и активностей»

**Текущее состояние:** интегрированные личные цели реализованы в `main`, версия выпуска пока не назначена. Не путать с удалённой первой реализацией; отдельного маршрута списка `/goals` нет. Функцию нельзя считать прошедшей пользовательскую приёмку до результатов QA.

## Навигация и сценарии

- Вторая `SMmainButt` ведёт на `/habit` с неизменным описанием «Планы, цели и ваш прогресс.». Никаких отдельных пунктов «Цели» в меню аккаунта.
- В `SMnavExtraDiv.habits` и `SMcreateDiv` пункт «Новая цель» с одинаковым SVG `BookmarkSimpleIcon` (`weight="fill"`); в extra-меню сохранены обработка мыши и touch `data-action="add-goal"`.
- В `HabitOverviewLayout` цели входят в общую строку `habitOverviewSummary` вместе с активностями и планами. Все три плашки одинакового стиля, распределяют ширину поровну, отображаются только при счётчике больше нуля. Активности/планы считаются за выбранный день, цели — все личные цели только для сегодняшнего и будущих дней; при выборе прошлой даты плашку целей не показывать. Нажатие на плашку открывает существующий `HabitOverviewList` с нужным фильтром или `GoalCatalog` со всеми целями; детали — `GoalDetails` через `Blackout`. Отдельного блока `GoalOverview`, локального плюса и кнопок «Показать все/ещё» в обзоре нет. Создание — из общего верхнего плюса через `PlanCreateMenu` (план, активность, цель) либо штатных пунктов SM; не добавлять плюс в каталог целей.
- Кнопка `habitUi.addGoal` уже существует в `HabitExtraButts` и `HabitHeaderMenu`; обе открывают **один** `GoalPicker`, где можно выбрать существующую цель либо создать новую с предвыбранной активностью. Из `AddHabit` кнопку цели не возвращать.
- У каждой цели самостоятельный статус, срок, необязательное описание, история изменений, связанные планы и активности. Удаление цели не удаляет исходные объекты.
- В `AccHabits` цели владельца профиля показаны счётчиком рядом с предстоящими планами; один ненулевой счётчик занимает всю ширину. Плашка открывает тот же `GoalCatalog` с `options.nick`. Пока модель owner-only, на чужом профиле личные цели не загружаются и не отображаются. Не подменять данные просматриваемого профиля целями текущего зрителя.

## Форма и компоненты

- `AddGoal` использует текущий `Blackout`, `TA`, `CalendarInput`, `SelectList`, поля с классами `addHabitInput` и систему `addPlanDiv`.
- В создании **нет SeekBar и нет input type=range**, ручной прогресс начинается с 0. Для изменения процента после создания в `GoalDetails` подключается настоящий `SeekBar` из `src/pages/Settings/components/SeekBar.tsx` с собственным SCSS. Описание компонента и владения касанием — в [CUSTOM_COMPONENTS.md](CUSTOM_COMPONENTS.md).
- Строка этапа: название + вес + кнопка удаления, каждая высотой `clamp(44px,5dvh,54px)`, поля и кнопки `height:100%`; для мобильной ширины используется `minmax(0,1fr)` без горизонтального переполнения. Вес по умолчанию 1.
- Новый UI живёт в `src/components/modules/scss/goalWorkspace.scss` и `src/pages/HabitPage/scss/goalWorkspace.scss`. Палитра, градиент, 24px, ограничения safe-area и жестов берутся из общих правил. RU/EN содержимое модалок находится в отдельных `goals.json`, загружаемых вместе с `/habit` и модулями, а не в стартовом bundle.

## Модель прогресса и API

- `manual`: ручное значение 0–100.
- `metric`: `(current-start)/(target-start)`, с поддержкой убывающей метрики и ограничением результата в 0–100.
- `milestones`: сумма весов выполненных этапов / сумма весов всех этапов; при пустом списке 0.
- `combined`: `metric_share * metric + (1-metric_share) * milestones`.
- `days` — количество выполненных запланированных дней с даты создания цели. `streak` — максимальная серия запланированных дней, выходные по периодичности не прерывают серию. `daily_timer` — количество запланированных дней, когда у каждой связанной запланированной активности набрано заданное число минут завершённых таймеров без пауз. Все три режима требуют хотя бы одну личную активность и целевое число дней. Учитываются everyday/weekly/cycle/sometimes (для sometimes — явный план или выполнение), даты начала/конца, часовой пояс действующего календаря Europe/Moscow. Незавершённый сегодняшний день не ломает серию. Текущая периодичность применяется к истории; история изменений расписания отдельно не хранится.
- Связи many-to-many выбираются прямо в AddGoal, при редактировании предзаполняются. Из активности исходная активность уже выбрана. В автоматическом режиме планы остаются связанными действиями, но не дают второй зачёт. 100% не меняет статус автоматически.
- Серверная миграция `at_goal_activity_progress.sql` добавляет target_days/daily_minutes; атомарный RPC `at_update_goal_and_links` обновляет поля и связи с owner ACL. Проверка после выпуска: дни недели, цикл, пропуск, таймер с паузами, переход полуночи, предварительно заполненные связи.
- Серверный API `/goal-workspace` и миграция `database/at_goals_integrated_20261124.sql` (пять закрытых таблиц `at_goal*`): owner-only доступ, RLS + REVOKE для anon/authenticated, единый источник данных на сервере. Не повторять удалённую `goals_personal_20261123`.
- Совместные цели, приглашения и публичные карточки **не реализованы** в первой версии. Не расширять доступ от связи с общей активностью.
