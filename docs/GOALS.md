# Цели внутри «Планов и активностей»

**Текущее состояние:** интегрированные личные цели реализованы в `main`, версия выпуска пока не назначена. Не путать с удалённой первой реализацией; отдельного маршрута списка `/goals` нет. Функцию нельзя считать прошедшей пользовательскую приёмку до результатов QA.

## Навигация и сценарии

- Вторая `SMmainButt` ведёт на `/habit` с неизменным описанием «Планы, цели и ваш прогресс.». Никаких отдельных пунктов «Цели» в меню аккаунта.
- В `SMnavExtraDiv.habits` и `SMcreateDiv` пункт «Новая цель» с одинаковым SVG `BookmarkSimpleIcon` (`weight="fill"`); в extra-меню сохранены обработка мыши и touch `data-action="add-goal"`.
- В `HabitOverviewLayout` цели входят в общую строку `habitOverviewSummary` вместе с активностями и планами. Все три плашки одинакового стиля, распределяют ширину поровну, отображаются только при счётчике больше нуля. Активности/планы считаются за выбранный день, цели — все личные цели только для сегодняшнего и будущих дней; при выборе прошлой даты плашку целей не показывать. Нажатие на плашку открывает существующий `HabitOverviewList` с нужным фильтром или `GoalCatalog` со всеми целями; детали — `GoalDetails` через `Blackout`. Отдельного блока `GoalOverview`, локального плюса и кнопок «Показать все/ещё» в обзоре нет. Создание — из общего верхнего плюса через `PlanCreateMenu` (план, активность, цель) либо штатных пунктов SM; не добавлять плюс в каталог целей.
- В `HabitExtraButts` и `HabitHeaderMenu` одна кнопка: «Добавить цель» при отсутствии связей, «Цели» при наличии хотя бы одной связанной цели. Обе переключают штатный `HabitMenu` на слайд `goals` с `GoalPicker slideHabitId` текущей активности; отдельной модалки списка из активности нет. Связанные цели определяются по `habit_ids` в owner-only списке API, показаны с названием, процентом и индикатором прогресса. «Записать прогресс» у активных ручных, числовых, этапных и комбинированных целей открывает существующие контролы `GoalDetails`; автоматические цели только показывают рассчитанный прогресс. Кнопка редактирования открывает `AddGoal` с ID цели. Добавить новую или привязать ещё одну можно из того же слайда; связанные цели исключены из списка привязки. После изменения обновляется список и надпись кнопки через `at-goals-updated`. В слайде для любого типа активности `SelectList` выбирает закреплённую цель среди связанных активных/приостановленных и повторяющихся завершённых или «Не показывать». Выбор локальный, изолирован по аккаунту и ID активности, синхронизируется между слайдом и индикатором. На текущем дне отображаются общий серверный процент цели и отдельный процент сегодняшнего запланированного дня, если он есть. Успешные изменения активности обновляют их без скелетона; для таймера используется минутное обновление при видимом приложении, общий зачёт только после завершения сеанса. На прошлых днях и чужих активностях индикатор скрыт. Из `AddHabit` кнопку цели не возвращать.
- У каждой цели самостоятельный статус, срок, необязательное описание, история изменений, связанные планы и активности. Удаление цели не удаляет исходные объекты.
- В `AccHabits` цели владельца профиля показаны счётчиком рядом с предстоящими планами; один ненулевой счётчик занимает всю ширину. Плашка открывает тот же `GoalCatalog` с `options.nick`. Пока модель owner-only, на чужом профиле личные цели не загружаются и не отображаются. Не подменять данные просматриваемого профиля целями текущего зрителя.

При вводе числового показателя, порога или процента этапа поле можно очистить и набрать значение заново. Для активного режима обязательные поля проверяются при сохранении. Для процента этапа допустим явный ноль. Статус, этапы, ручной прогресс и связи с активностями отображаются сразу в карточке и открытых списках. При отказе сервера возвращается подтверждённое состояние, введённое значение можно исправить и отправить повторно.

## Форма и компоненты

- `AddGoal` использует текущий `Blackout`, `TA`, `CalendarInput`, `SelectList`, поля с классами `addHabitInput` и систему `addPlanDiv`.
- В создании **нет SeekBar и нет input type=range**, ручной прогресс начинается с 0. Для изменения процента после создания в `GoalDetails` подключается настоящий `SeekBar` из `src/pages/Settings/components/SeekBar.tsx` с собственным SCSS. Описание компонента и владения касанием — в [CUSTOM_COMPONENTS.md](CUSTOM_COMPONENTS.md).
- Этапы — вручную отмечаемые шаги к цели. Видны только для режимов `milestones` и `combined`; вместо веса пользователь задаёт достигнутый после завершения этапа процент 0–100 с шагом 0,01. Для других режимов блок скрыт, существующие этапы не удаляются при переключении режима.
- Строка этапа: название + процент + кнопка удаления, каждая высотой `clamp(44px,5dvh,54px)`, поля и кнопки `height:100%`; для мобильной ширины используется `minmax(0,1fr)` без горизонтального переполнения. Новый этап по умолчанию имеет порог 100%; при нескольких этапах проценты можно изменить.
- Новый UI живёт в `src/components/modules/scss/goalWorkspace.scss` и `src/pages/HabitPage/scss/goalWorkspace.scss`. Палитра, градиент, 24px, ограничения safe-area и жестов берутся из общих правил. RU/EN содержимое модалок находится в отдельных `goals.json`, загружаемых вместе с `/habit` и модулями, а не в стартовом bundle.

## Модель прогресса и API

- `manual`: ручное значение 0–100.
- `metric`: `(current-start)/(target-start)`, с поддержкой убывающей метрики и ограничением результата в 0–100.
- `milestones`: наибольший `completion_percent` среди выполненных этапов; при пустом списке 0. Например, выполненный этап 60% и невыполненный 100% дают 60%. Существующие этапы мигрированы в явные проценты без изменения уже достигнутого прогресса; прежние веса сохраняются только для обратной совместимости. Устаревший клиент без явных процентов по-прежнему поддерживается сервером.
- `combined`: `metric_share * metric + (1-metric_share) * milestones`.
- `days` — количество выполненных запланированных дней с даты создания цели. `streak` — максимальная серия запланированных дней, выходные по периодичности не прерывают серию. `daily_timer` — количество запланированных дней, когда у каждой связанной запланированной активности набрано заданное число минут завершённых таймеров без пауз. Все три режима требуют хотя бы одну личную активность и целевое число дней. Учитываются everyday/weekly/cycle/sometimes (для sometimes — явный план или выполнение), даты начала/конца, IANA-пояс пользователя (сервер использует синхронизированную настройку напоминаний или текущий запрос). Незавершённый сегодняшний день не ломает серию. Текущая периодичность применяется к истории; история изменений расписания отдельно не хранится.
- `daily_counter` — число запланированных дней, в которые каждая запланированная связанная активность достигла порога `metric_target` по фактическому дневному `habit_counters.count`. Целевое значение целое положительное, число дней — `target_days`.
- Новые связи только с собственными ongoing-активностями и предстоящими планами (`upcoming`, ещё не истекла дата/время в календарном поясе пользователя). Архивные/завершённые/отменённые не предлагаются; сервер проверяет также прямые API-запросы. Существующие старые связи сохраняются до явной отвязки.
- Связи many-to-many выбираются прямо в AddGoal, добавляются сразу по выбору SelectList, одинаково при входе из активности и с общего плюса; при редактировании предзаполняются. Из активности исходная активность уже выбрана. В автоматическом режиме планы остаются связанными действиями, но не дают второй зачёт. Автозавершение опционально, по умолчанию выключено. При включении 100% переводит активную цель в completed; при снижении процента автоматически закрытая цель вновь становится активной. Ручное завершение сохраняется.
- Серверная миграция `at_goal_activity_progress.sql` добавляет target_days/daily_minutes; атомарный RPC `at_update_goal_and_links` обновляет поля и связи с owner ACL. Проверка после выпуска: дни недели, цикл, пропуск, таймер с паузами, переход полуночи, предварительно заполненные связи.
- Серверный API `/goal-workspace` и миграция `database/at_goals_integrated_20261124.sql` (пять закрытых таблиц `at_goal*`): owner-only доступ, RLS + REVOKE для anon/authenticated, единый источник данных на сервере. Не повторять удалённую `goals_personal_20261123`.
- Совместные цели, приглашения и публичные карточки **не реализованы** в первой версии. Не расширять доступ от связи с общей активностью.

## Обновление, история и сроки

Один кэш `useGoalsWorkspace` на аккаунт и IANA timezone; подписчики получают одинаковый список, одновременные события объединяются. Успешные мутации активности обновляют список, включая отмену выполнения и расписание. Серверная очередь at_goal_dirty пересчитывает сохранённые изменения независимо от открытого клиента. В деталях кнопка с иконкой истории открывает отдельную вложенную модалку `GoalHistory` через Blackout; в ней показывается история фактических изменений процента (from/to) и остальные события (до 30 последних записей API); это не реконструкция прежнего расписания. Каталог открывается на активных, завершённые сортируются по дате завершения.

Форма содержит Checkbox автозавершения и SelectList напоминания о сроке: выключено, в день срока, за 1/3/7/14/30 дней. При удалении срока напоминание отключается. Web Push отправляется после 09:00 в выбранный день в часовом поясе аккаунта с учётом общего запрета уведомлений и действующей подписки. Серверная миграция `at_goal_final_progress.sql` хранит состояние и историю, очередь пересчёта и уникальный ключ доставки. Дневные отметки выполнения остаются гражданскими датами; таймеры распределяются по реальным границам дня; счётчики привязаны к дате сохранённой строки, исторические данные не переписываются.

## Проверка

Проверять раздельно: исходники, сборки и CI, применённую миграцию, точные коммиты Vercel/Render, затем пользовательский сценарий. Нужны две учётные записи для проверки owner ACL и реальный iPhone Safari для клавиатуры, нижних полей, действий `SMnavExtra`, drag SeekBar и жестов 350ms. Открытые пункты вести в [RELEASE_QA.md](RELEASE_QA.md) и [Linear ONE4SV-16](https://linear.app/atone4sv/issue/ONE4SV-16).

В слайде целей заголовок «Связать существующую цель» имеет размер 16px, как обычный текст действий; не оформлять его как мелкую подпись.

В форме AddGoal режимы `daily_timer` и `daily_counter` доступны только после выбора связанных активностей соответствующего `metric_type` (`settings` или `habits_settings` в API списка); смешанные типы не допускаются для этих режимов на клиенте. При несовместимой связи сохранение блокируется до выбора подходящего режима или изменения связей.

`total_timer` доступен только для связанных timer-активностей, задаёт суммарное целевое время в минутах через `metric_target`, без поля количества дней. Засчитываются завершённые сеансы с гражданской даты создания цели до срока или текущего момента без пауз. Режимы `daily_timer`/`total_timer` требуют timer, `daily_counter` — counter; связи с несовместимыми типами запрещены на клиенте и сервере. Миграция сервера `at_goal_stage_percent_total_timer.sql` добавляет `completion_percent`, режим и триггер пересчёта при изменении `metric_type`; `at_goal_backfill_stage_percent.sql` фиксирует проценты старых этапов.

## Повторение и закреплённая цель

`AddGoal`: без сброса, каждый день, неделю (понедельник), месяц (первое число). Первый период начинается в день включения, последующие — с календарной границы 00:00 в синхронизированном часовом поясе аккаунта. В новом периоде ручной процент становится 0, числовая метрика возвращается к начальному значению, отметки этапов сбрасываются, автоматический расчёт ограничен датами периода. Завершённая повторяющаяся цель возвращается в активные. История `GoalHistory` отдельно показывает закрытые периоды с датами, процентом и выполнением, по 50 с догрузкой. Срок завершает повторение; архив и отмена останавливают его. Server worker и чтение/изменение цели закрывают период транзакционно; пропущенные периоды догоняются. `at_goal_periods` owner-only через API, RLS/REVOKE.

В настройках активностей локальный переключатель `settings_show_habit_goals` по умолчанию включён. При выключении скрываются полосы закреплённой цели в SM и блоке выполнения, выбор закрепления не удаляется. Закрепление одно на активность/аккаунт (`useHabitGoalDisplay`), в том числе для обычных активностей. Существующие ограничения таймерных и счётчиковых режимов сохраняются. В SM только собственные ongoing-активности с выбранной актуальной целью увеличивают высоту; остальные карточки не меняются. Прогресс берётся из общего `useGoalsWorkspace`, без отдельного запроса на каждую карточку.

### Итоги дня и последние записи

В правой колонке и `HabitOverviewList` фильтр «Цели», в общих итогах отдельный счётчик уникальных целей, фактически достигнутых в выбранную дату (`GET /goal-workspace/day/:date`). В прошлом видны завершённые в эту дату цели, не текущее состояние всех целей. Слайд `GoalPicker` показывает две последние выполненные стадии с датами или фактические записи таймера/счётчика/дней/изменения процента; таймер без пауз. Даты через `formatAppDate` и `formatAppTime`. В `AddGoal` SelectList имеет рамку как поля ввода; подпись автозавершения кликабельна, как подписи этапов.

### Совместные цели

В `HabitChatMenu` после разрешений выполнения и комментариев: «Цели активности» (у каждого свои / одна общая) и, для общей цели, «Выполнение общей цели» (вместе / самостоятельно). Меняет владелец, участники видят значения. При общей цели создаётся явная отдельная definition без других ссылок; существующие личные цели остаются приватными. В режиме самостоятельного выполнения экземпляр с тем же определением, но своим прогрессом и отметками, создаётся для участника при доступе. В общем режиме прогресс один; право `can_complete` требуется для записи, структура принадлежит владельцу. Слайд, индикатор SM и завершение используют действующую scope и текущий экземпляр, без показа чужих личных целей.

При самостоятельном выполнении отдельный экземпляр создаётся также владельцу; его общая и индивидуальная история независимы. Владелец открывает определение из экземпляра через «Настроить общую цель» для изменения структуры и этапов. Автоматический расчёт при общей метрике самой активности использует её общие данные; ручные отметки остаются отдельными. Под баром максимум две записи суммарно, включая комбинированную цель.

### Дневной прогресс в календаре
`HoverDay` / `DaySummary` запрашивает выбранный день: для активности — `GET /goal-workspace/activity/:habitId/day/:date`, для общего календаря — количество завершённых целей дня. Для ручного прогресса показано изменение за день, для автоматического — расчёт по данным дня; неизвестный исторический процент отображается как «—», а не подменяется текущим. Доступ определяется членством и ACL целей. Та же сводка используется над действиями ПКМ и под неподвижным мобильным календарём; при запросе виден скелетон, размеры мобильной сводки зарезервированы.

Закрепление цели: при первом открытии на устройстве без сохранённого выбора автоматически показывается первая подходящая актуальная цель (по ID); явное «Не показывать» хранится как `none`. Загрузка общего кэша не зависит от наличия локального выбора. Полоса в `Complete` доступна любому типу активности на ПК и телефоне, но таймерные/счётчиковые автоматические цели по-прежнему требуют соответствующей метрики. Выбор пока локален для устройства, не синхронизируется между устройствами.
