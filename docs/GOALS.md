# Цели внутри «Планов и активностей»

**Текущее состояние:** новая реализация интегрированных личных целей находится в ветке `feature/goals-integrated-habit`, версия выпуска пока не назначена. Не путать с удалённой первой реализацией; отдельного маршрута списка `/goals` нет. Функцию нельзя считать прошедшей пользовательскую приёмку до результатов QA.

## Навигация и сценарии

- Вторая `SMmainButt` ведёт на `/habit` с неизменным описанием «Планы, цели и ваш прогресс.». Никаких отдельных пунктов «Цели» в меню аккаунта.
- В `SMnavExtraDiv.habits` пункт «Добавить цель» с обработкой mouse и touch `data-action`, в `SMcreateDiv` — «Новая цель».
- `HabitOverviewLayout` импортирует `GoalOverview`; список до четырёх активных/приостановленных целей расположен в существующем центральном блоке вместе с итогами дня. «Показать все» открывает `GoalCatalog` через `Blackout`, а просмотр/редактирование — `GoalDetails`, не отдельный route.
- Кнопка `habitUi.addGoal` уже существует в `HabitExtraButts` и `HabitHeaderMenu`; обе открывают **один** `GoalPicker`, где можно выбрать существующую цель либо создать новую с предвыбранной активностью. Из `AddHabit` кнопку цели не возвращать.
- У каждой цели самостоятельный статус, срок, необязательное описание, история изменений, связанные планы и активности. Удаление цели не удаляет исходные объекты.

## Форма и компоненты

- `AddGoal` использует текущий `Blackout`, `TA`, `CalendarInput`, `RadioGroup`, поля с классами `addHabitInput` и систему `addPlanDiv`.
- В создании **нет SeekBar и нет input type=range**, ручной прогресс начинается с 0. Для изменения процента после создания в `GoalDetails` подключается настоящий `SeekBar` из `src/pages/Settings/components/SeekBar.tsx` с собственным SCSS. Описание компонента и владения касанием — в [CUSTOM_COMPONENTS.md](CUSTOM_COMPONENTS.md).
- Строка этапа: название + вес + кнопка удаления, каждая высотой `clamp(44px,5dvh,54px)`, поля и кнопки `height:100%`; для мобильной ширины используется `minmax(0,1fr)` без горизонтального переполнения. Вес по умолчанию 1.
- Новый UI живёт в `src/components/modules/scss/goalWorkspace.scss` и `src/pages/HabitPage/scss/goalWorkspace.scss`. Палитра, градиент, 24px, ограничения safe-area и жестов берутся из общих правил. RU/EN содержимое модалок находится в отдельных `goals.json`, загружаемых вместе с `/habit` и модулями, а не в стартовом bundle.

## Модель прогресса и API

- `manual`: ручное значение 0–100.
- `metric`: `(current-start)/(target-start)`, с поддержкой убывающей метрики и ограничением результата в 0–100.
- `milestones`: сумма весов выполненных этапов / сумма весов всех этапов; при пустом списке 0.
- `combined`: `metric_share * metric + (1-metric_share) * milestones`.
- Планы и активности имеют many-to-many связи, их выполнение не прибавляется второй раз. 100% не меняет статус цели автоматически.
- Серверный API `/goal-workspace` и миграция `database/at_goals_integrated_20261124.sql` (пять закрытых таблиц `at_goal*`): owner-only доступ, RLS + REVOKE для anon/authenticated, единый источник данных на сервере. Не повторять удалённую `goals_personal_20261123`.
- Совместные цели, приглашения и публичные карточки **не реализованы** в первой версии. Не расширять доступ от связи с общей активностью.
