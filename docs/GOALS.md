# Цели внутри «Планов и активностей»

**Статус — проектирование.** Требования ниже относятся к будущей реализации в `/habit`. В dev 0.6.5 Mosaic отдельного маршрута `/goals` и формы создания цели нет. Версия выпуска ещё не назначена.

## 1. Куда встраивается функция

- Единственный основной обзор **«Планы и активности»** — существующий `/habit` и `HabitOverviewLayout`; отдельной индексной страницы `/goals` **нет**. Обзор целей нужно проектировать в структуре существующих колонок: календарь слева, центр с общей сводкой, правый блок с текущими действиями. Не заменять эту компоновку самостоятельным экраном.
- Детальный просмотр отдельной цели допускается только как подчинённая сущности карточка/модалка либо маршрут `/goal/:id` **после отдельного UX-решения**; не создавать параллельный хаб. При выборе ориентироваться на путь `/plan/:id` без дублирующего экрана списка планов.
- В **`AccountList.tsx`** остаются **ровно существующие основные навигационные карточки**: лента и `/habit`. У второй `SMmainButt` текущее описание `accountNavigation.activitiesDesc` уже равно **«Планы, цели и ваш прогресс.»** — не добавлять рядом отдельную кнопку «Цели». Название второй кнопки «Планы и активности» менять только по отдельному требованию.
- В **`SMnavExtraDiv.habits`** добавить третье действие **«Добавить цель»** рядом с добавлением активности и плана. Учитывать **оба** существующих пути активации в `SMnav.tsx`: `onMouseUp` и мобильное завершение по `data-action` через `elementFromPoint`, с закрытием extra-меню.
- В глобальном блоке **`SMcreateDiv`** добавить **«Новая цель»** (а не отдельную навигационную кнопку); использовать имеющиеся правила кнопок и переводы RU/EN.
- В существующем обзоре `/habit` есть кнопка `habitOverviewAddButton`, открывающая штатный `PlanCreateMenu`; её меню также должно учитывать создание цели только если это согласовано с UX — не вставлять дубли без проверки.
- В `HabitExtraButts.tsx` и `HabitHeaderMenu.tsx` уже **есть** действие `habitUi.addGoal` для отдельной активности, сегодня оно вызывает `showDevNote()`. Переподключить **эти существующие точки** к сценарию «связать активность с существующей целью / создать цель с предвыбранной активностью». Не создавать вторую одинаковую кнопку. Сохранить общий `addGoalButtDiv`, используемый также для сотрудничества/настроек.
- В модалке **`AddHabit`** кнопку `addHabitGoal` **удалить окончательно**; создание активности не должно сопровождаться отдельной кнопкой цели внизу формы.

## 2. Что означает цель

Цель = ожидаемый результат, план = одноразовое действие, активность = регулярное действие. Личные и совместные цели — дальнейшее развитие одной сущности, но первая итерация ограничена личными целями. Связанные планы/активности не должны храниться копиями внутри цели.

Поля: название (обязательное), описание (необязательное), срок (необязательный), статус, режим отслеживания, этапы (необязательные, вес по умолчанию `1`), связи со своими планами и активностями (many-to-many). Удаление цели не удаляет исходные планы/активности.

## 3. Расчёт прогресса

- **Ручной:** 0–100%; прогресс начинается с `0`; **в модалке создания нет ползунка вообще**.
- **Числовой:** начало, текущее значение, целевое значение, единица измерения. Результат нормализуется к `0..100`; уменьшение метрики тоже поддерживается.
- **По этапам:** сумма весов выполненных / общая сумма весов; при отсутствии этапов — 0. Вес `1` по умолчанию, может быть изменён позднее.
- **Комбинированный:** доля числового прогресса и этапов; выбирать только при наличии валидных обоих источников.
- Вклад планов и активностей **не прибавляется автоматически** вторично. Выполнение связанного плана может предложить завершить соответствующий этап, но не менять результат молча.
- `100%` не равен автоматической смене статуса на «Достигнута»: завершение подтверждается пользователем.

Если при последующем редактировании действительно нужен интерактивный процент, **использовать штатный `SeekBar`** из `src/pages/Settings/components/SeekBar.tsx`, а не `<input type="range">`. По умолчанию не выводить ползунок в создании и не дублировать число в подписи.

## 4. Дизайн формы и этапов

- Сначала изучить существующие `AddHabit`, `AddPlan`, `PlanEditor`, `Blackout`, `RadioGroup`, `SelectList`, `TA`, `CalendarInput`, `ConfirmAction` и соответствующие SCSS. Использовать единую модалку `Blackout` без второго слоя. Новые строки — одновременно RU/EN.
- Форма: название, описание, срок, способ расчёта; количественные поля показывать только если они нужны, блок этапов — необязательный.
- **Одна строка этапа:** поле названия (растягивается), поле веса (компактное), кнопка удаления **той же высоты, что поля**; одинаковое вертикальное выравнивание, единые паддинги, обычный значок крестика. Никакой маленькой круглой кнопки рядом с высокими инпутами. На телефоне все элементы остаются внутри экрана без горизонтального overflow; область нажатия достаточная.
- Стили только в существующей структуре `scss/`; динамические цвета из темы, градиентные кнопки без декоративного border; шрифт нового действия 16px. Учитывать `safe-area` и клавиатуру.
- Загрузки и ошибки оформлять как в текущих модалках; не подменять реальную ошибку пустым состоянием.

## 5. Архитектура данных — новая реализация, не прежняя схема

Не повторно применять предыдущую SQL-миграцию `goals_personal_20261123` и не оживлять удалённые маршруты без проверки модели. Перед кодом уточнить структуру целей в сервере, табличные связи и ACL; личные цели по умолчанию приватны. Подумать, как показывать связанное действие в нескольких целях, не удваивая прогресс. Состояние и изменения — серверные, не локальные.

Первая реализация в строгом порядке: (1) модалка и единый сценарий создания; (2) интеграция списка/прогресса в `/habit`; (3) связывание из существующих действий активности; (4) ручное/числовое/этапное/комбинированное отслеживание; (5) безопасный API, миграция, RU/EN и история; (6) тесты и публикация. Не переносить старые файлы `GoalsPage`/`AddGoal` как готовые UI без пересмотра.

## 6. Приёмка перед выпуском

1. Вторая `SMmainButt` остаётся переходом в `/habit`, описание **«Планы, цели и ваш прогресс.»**; никаких самостоятельных «Цели» в меню аккаунта или маршрута `/goals`.
2. В `SMnavExtra.habits` **«Добавить цель»** срабатывает на ПК и iPhone; в глобальном `create` — **«Новая цель»**.
3. В `AddHabit` нет `addHabitGoal`; существующая кнопка цели в `HabitExtraButts` и контекстном меню однажды начинает вести в единый сценарий связывания, без дублей.
4. В создании нет `range`/`SeekBar`; у удаления этапа одинаковая высота с соседними полями, клавиатура и safe-area не обрезают действия.
5. Проверить четыре расчёта, веса этапов, изменение направления метрики, привязку/отвязку и сохранность исходных объектов после удаления цели.
6. Проверить приватность двумя аккаунтами, неавторизованный доступ, iPhone Safari, RU/EN, жесты 350 мс и сборку клиента/сервера на **текущих SHA**.
