# SCSS в AchieveTogether: структура, оформление и правила

Правила текстовых полей и owner: [V0_6_FEATURES_AND_QA.md](V0_6_FEATURES_AND_QA.md).

Документ для работы со стилями клиентского репозитория [one4sv/AT](https://github.com/one4sv/AT). Составлен по существующим `src/scss`, SCSS страниц и рабочим инструкциям проекта. **Перед изменением интерфейса прочитать этот файл, [CODE_STYLE.md](CODE_STYLE.md) и [CUSTOM_COMPONENTS.md](CUSTOM_COMPONENTS.md).** Текущий исходник в `main` важнее устаревшего примера.

## 1. Где какие стили

| Что | Где |
| --- | --- |
| Входная точка общих стилей | `src/scss/App.scss` |
| Карты тем, акцентов, градиентов, оформления | `src/scss/_variables.scss` |
| Общие миксины (input, modal, selectList и т. д.) | `src/scss/_mixins.scss` |
| Сброс и общая типографика/поведение | `src/scss/_reset.scss`, `src/scss/_global.scss` |
| Общие анимации | `src/scss/_animations.scss` |
| Модальная оболочка | `src/scss/blackout.scss` |
| Стили общих компонентов | `src/scss/radioGroup.scss`, `selector.scss`, `toggler.scss`, `Composer.scss`, `ContextMenu.scss`, `Loading.scss` и другие |
| Стили модалок | `src/scss/modules/` |
| Стили бокового меню | `src/scss/SM/` |
| Страницы | `src/pages/<НазваниеСтраницы>/scss/` |

При небольшой правке сохранять существующий файл и его структуру. Не заводить новые «вторые» стили поверх старых, не переносить селекторы без причины. Перед правкой найти все упоминания класса и проверить, откуда именно импортируется SCSS.

`App.scss` подключает `variables`, `mixins`, `reset`, `animations`, `datepicker`, `global` и генерирует CSS-переменные тем с помощью миксинов. Компонентные SCSS обычно импортируются самими компонентами.

## 2. Стиль написания

- **4 пробела для одного уровня вложенности**, без табуляции.
- **Каждый селектор и каждое CSS-свойство с новой строки**. Не объединять декларации в одну строку.
- Пробел до `{`, после `:`; точка с запятой в конце каждой декларации.
- Сначала геометрия и базовый вид блока, затем дочерние элементы/состояния, затем адаптивность — если файл уже организован иначе, следовать его локальному стилю.
- SCSS разрешает вложенность и `&` для состояний, но не делать глубокую цепочку без необходимости.
- Не добавлять `!important` как стандартное решение конфликтов специфичности; сначала найти источник конфликта.
- **Никогда не добавлять и не переопределять `font-weight`** без прямого требования автора.
- Не форматировать чужие правила и импорты только ради единообразия.

Пример оформления:

```scss
@use "../mixins.scss" as var;

.exampleBlock {
    width: 100%;
    min-width: 0;
    display: flex;
    align-items: center;
    gap: .5vw;
    padding: 1dvh 1vw;
    border-radius: 24px;
    background-color: var(--mc);
    color: var(--tc);

    > svg {
        flex-shrink: 0;
        color: var(--accent_text);
    }

    @media (hover: hover) {
        &:hover {
            background-color: var(--menuButtHover);
        }
    }

    @media (max-width: 800px) {
        padding: 1dvh 3vw;
    }
}
```

## 3. Единицы и адаптивность

| В задаче | Использовать |
| --- | --- |
| Относительная ширина страницы или панели | `vw`, `%` |
| Высота панели/окна/элемента | `dvh` (особенно на телефоне), при соответствии соседнему коду допустимо `vh` |
| Отступы и промежутки | `vw`, `vh`/`dvh` по окружающему SCSS |
| Распределение пространства | `flex: 1`, `min-width: 0`, `min-height: 0`, `auto` |
| Тонкая граница | `1px` |
| Обычное скругление блоков/полей/кнопок | **`24px`** |
| Мобильный breakpoint, существующий в проекте | `800px` |
| Размер текста и SVG | Следовать существующим `px`, `em`, `rem` и пропсам иконок; не менять без причины |

Не переводить механически всё в пиксели или всё во viewport-единицы. Для вертикально растянутой области со скроллом использовать `flex: 1`, `min-height: 0`, `overflow-y: auto` **на нужном внутреннем контейнере**, а не вычислять фиксированную высоту в JavaScript.

Мобильные модалки на `max-width: 800px`: **`width: 100%` без боковых зазоров**, учитывать `env(safe-area-inset-bottom)` и `100dvh`, не блокировать клавиатурой содержимое и действия. Проверь реальный iPhone/Safari, а не только режим эмуляции.

## 4. SCSS-переменные и CSS-токены тем

**Это разные механизмы:**

- `$name` — значение Sass во время сборки. Пример: `$block_border` в `src/scss/_variables.scss`.
- `var(--name)` — CSS-переменная браузера, меняющаяся при выборе темы/акцента/декора.

В `_variables.scss` находятся карты `$themes`, `$accents`, `$grads`, `$decors`. Миксины `generate-theme-vars`, `generate-accent-vars`, `generate-grad-vars`, `generate-decor-vars` генерируют свойства для атрибутов `data-theme`, `data-accent`, `data-grad`, `data-decor`. `src/theme-init.ts` устанавливает эти атрибуты на `document.documentElement`.

**Основные токены, которые нужно отличать:**

| Токен | Назначение |
| --- | --- |
| `--bgc` | Основной фон приложения; выбирать для **непрозрачных поверхностей** там, где нельзя просвечивать текст под списком |
| `--mc` | Поверхность модального/основного блока; **может быть полупрозрачной в glass-декоре** |
| `--interact` | Поверхность взаимодействия, полей и кнопок; тоже может иметь прозрачность |
| `--tc` | Основной цвет текста |
| `--borderWh`, `--borderHabit` | Нейтральные линии и приглушённые элементы |
| `--block_border` | Сгенерированная CSS-переменная тонкой границы |
| `--accent`, `--accent_text` | Акцент и акцентный текст |
| `--grad` | Второй цвет пользовательского градиента |
| `--menuButtHover` | Фон при взаимодействии |
| `--blur` | Токен размытия, когда он предусмотрен оформлением |

**Важно:** `$block_border` в Sass и `var(--block_border)` в CSS — разные сущности. В проекте CSS-вариант создаётся через `generate-theme-vars`. Не переносить Sass-переменную в `var()` наугад.

Нельзя вписывать фиксированный оранжевый, зелёный или фиолетовый: акцент пользователя может отличаться. Для градиента пользоваться `linear-gradient(135deg, var(--accent), var(--grad))`.

## 5. Glass и непрозрачные выпадающие списки

При `data-decor="glass"` токены `--mc` и `--interact` могут содержать альфу. Это нормально для внешней стеклянной поверхности, **но не для всплывающего списка поверх текста**. Иначе сквозь пункты видны участники или содержимое заднего плана.

**Правило:** у раскрытого `SelectList` фон **самого списка** задавать `background-color: var(--bgc)`. При этом входное поле выбора и фон модалки могут сохранить собственные `--mc` / `--interact`.

Конкретный пример: `src/scss/modules/PermissionsDiv.scss` — `.rolesModalSelect`. Там у `@include var.selectList(...)` параметр `$bg` теперь `var(--bgc)`, а `> input` по-прежнему использует `var(--mc)`.

```scss
.rolesModalSelect {
    @include var.selectList(
        100%, 4.5dvh, 2.2dvh, .75vw, 1.1dvh,
        var(--borderWh), var(--tc), var(--bgc),
        16px, .8dvh, .75vw, .25dvh
    );

    > input {
        background: var(--mc);
    }
}
```

**Не исправлять прозрачность увеличением `z-index`**: `z-index` определяет порядок наложения, но не делает фон непрозрачным. Проверять `overflow: hidden/auto` у родителя: он может обрезать выпадающий список даже при большом `z-index`. Если popup выходит за прокручиваемую область, проверить архитектуру позиционирования — не ставить бессистемно `z-index: 99999`.

## 6. Миксины: что уже есть

Исходники в `src/scss/_mixins.scss`:

- `@include var.input($bg, $c, $bor, $h, $br, $bh, $w: null)` — поле ввода и фокус.
- `@include var.inputGlow($line, $lineGlow, $focusLine, $focusGlow)` — светящаяся линия поля.
- `@include var.longButt($w, $h, $padd-h, $padd-w, $bg, $c, $bord, $hov: null)` — длинная кнопка.
- `@include var.gradButt($w, $h, $padd-h, $padd-w, $grad, $gradH, $c, $shad)` — градиентная кнопка.
- `@include var.centerModal` — позиционирование модалки (включая `position`, `left`, `top`, **`transform`**).
- `@include var.centerTopModal` — близкий вариант с другой вертикальной позицией.
- `@include var.selectList($w, $h, $wI, $r, $t, $c, $ac, $bg, $fs, $ph, $pw, $tY, $upwards: false)` — позиция поля, стрелки, выпадающего списка, анимация и пункты.

Используемый импорт:

```scss
@use "../mixins.scss" as var;

.myElement {
    @include var.centerModal;
}
```

Путь `@use` рассчитывается **от файла SCSS**, а не от TSX. Внутри `src/pages/HabitPage/scss/` он другой, например `@use "../../../scss/mixins" as var;`.

`@include var.selectList` настраивает **первого прямого дочернего `div`** как выпадающее меню. Не путать его с корневым `.selectListDiv` или `> input`. Смотри [CUSTOM_COMPONENTS.md](CUSTOM_COMPONENTS.md) и реальные примеры `.redHabitSL`, `.rolesModalSelect`.

## 7. Модалки, вложенность, слайдеры

### Обязательное оформление модальных окон AT

- **Корневая поверхность модалки — `background: var(--mc)`**, а не `var(--bgc)`. При стеклянной теме сохранить прозрачность и размывать содержимое позади: `backdrop-filter: blur(var(--blur));` и `-webkit-backdrop-filter: blur(var(--blur));`.
- **`var(--bgc)` — фон приложения и отдельных непрозрачных выпадающих списков**, например раскрытого `SelectList`, где нужно гарантированно закрыть текст за списком. Это не фон самой модалки. Не путать popup-список с модальным окном.
- Открывать окна только через штатный `Blackout`. Внешний контейнер затемняет фон и обеспечивает общий blur; содержимое модалки остаётся отдельной стеклянной поверхностью. Не создавать собственный полноэкранный overlay.
- На ПК окно компактное и центрированное; на мобильном `width: 100%` без боковых зазоров, с `safe-area`, внутренним скроллом списка и скруглением верхних углов `24px`. Не добавлять дополнительную кнопку закрытия или вторую полоску `mobileBar` без требования.
- Для внутренних полей применять `var(--interact)` или существующий компонент. **Не наслаивать несколько одинаковых фонов** на родительскую панель и её дочерние блоки.
- У нейтрального стеклянного окна допустима штатная граница от `Blackout`; если у самой поверхности `background: linear-gradient(135deg, var(--accent), var(--grad))`, декоративный `border` должен быть `none`.
- Образец для новой модалки — `src/scss/modules/CreateChat.scss`; при изменении `QuickActionPicker` проверять `.quickActionModal` в `src/pages/Settings/components/SettingsTabs/QuickActionsSettings.scss`.



`Blackout` уже имеет оболочку `.blackout` / `.blackoutModule` и мобильную `.mobileBar` из `src/scss/blackout.scss`. Миксин `centerModal` задаёт `transform: translate(-50%, -50%)` для самого окна: **не применять этот миксин к движущемуся содержимому**, иначе `transform` перетрётся.

Для двух экранов внутри модалки:
- отдельная область просмотра с `overflow: hidden`;
- внутри неё `display: flex` и по панели `flex: 0 0 100%`;
- сдвиг панели через `translateX(-100%)`, без случайного центрирования;
- `min-height: 0` для вложенных flex-контейнеров;
- прокрутка в самой панели, нижние действия вне прокручиваемой части.

Пример готовой реализации: `src/scss/modules/PermissionsDiv.scss`: `.rolesModalViewport`, `.rolesModalTrack`, `.rolesModalPanel`. Прежде чем менять, открыть текущие селекторы и проверить их совместно.

Не добавлять модалкам крестик/«Отмена» автоматически. `Blackout` уже умеет закрывать по фону и жестом; для «Права и роли» действующее требование — без дополнительных кнопок закрытия. Мобильная полоска принадлежит **оболочке**, не дублировать её.

### Слои, акцентные цвета и опасные действия

- **Не оставлять акцентный SVG/текст непосредственно на голом фоне сайта или единственной поверхности `var(--mc)`.** Акцент выводить на отдельном контрастном слое `var(--interact)` внутри стеклянного родителя. Например, в настройках `.settingInnerDiv` (`--mc`) содержит `.quickActionsSettings` (`--interact`), а внутри него иконки `--accent_text`. Не использовать `background: transparent` вместо такого слоя.
- Все обычные SVG быстрых переходов — `color: var(--accent_text)`, для аватаров сохранять изображения. В контекстном меню быстрых действий сохранять **те же размеры и высоту строк**, что у стандартных `.ContextMenuButt`; не увеличивать строку дочерним SVG.
- **Любое удаление, выход, отключение с разрушительным результатом или другое опасное действие** оформлять по `.SMaccountButt.logout`: `color: var(--notValid)`, `border: 1px solid var(--notValid)` для отдельной кнопки, при hover/active `background: var(--notValidBg)`. Не применять к таким действиям `--accent`, `--menuButtHover` или цвет обычного подтверждения.
- Кнопки удаления быстрых действий `.quickActionRemove` следуют стилю logout; перетаскивание за `.quickActionDragHandle` с `ListIcon` в цвете `var(--borderWh)`. При удержании ручки запрещать прокрутку/обновление страницы, порядок сохранять только после завершения перетаскивания.
- Хедеры имеют hover для мыши, active для touch и отдельный активный класс на время долгого удержания. Базовый hover фон — `var(--menuButtHover)`, не акцент прямо на `--mc`.

## 8. Hover, active, focus

Разделять ПК с мышью и устройства с касанием:

```scss
.exampleButton {
    background: var(--mc);

    &:focus-visible {
        outline: 1px solid var(--accent);
    }

    @media (hover: hover) {
        &:hover {
            background: var(--interact);
        }
    }

    @media (hover: none) {
        &:active {
            background: var(--interact);
        }
    }
}
```

Не оставлять безусловный `:hover` на телефоне; не добавлять активной градиентной поверхности полупрозрачную обводку, которая создаёт грязные края. Для `.contactsUser.active` и градиентных основных кнопок использовать предусмотренный дизайн, без лишнего `outline`/альфа-бордера.

## 9. Типичные ошибки и как проверять

| Ошибка | Что проверять |
| --- | --- |
| Под списком виден текст других элементов | Прозрачный `--mc`/`--interact` у popup → `var(--bgc)` |
| Список обрезан | `overflow` родителя, stacking context, `position`, `z-index` |
| Слайдер показывает два экрана | Ширина viewport/track/panel, `flex-basis`, конфликт `transform` с миксином |
| Стили не применились | Путь `@use`/`@import`, импорт SCSS компонентом, селектор, приоритет правил |
| На iPhone окно обрезано | `100dvh`, safe-area, виртуальная клавиатура, вложенный скролл |
| Фон или акцент не соответствует персонализации | Жёсткий hex, неверный CSS-токен, атрибуты темы |
| Дублирующиеся отступы и радиусы | Повторные классы, старые правила ниже по файлу, вложенные контейнеры |
| Пропал blur | Непрозрачный дочерний слой или неверный `backdrop-filter` |
| У кнопки двукратный hover/tap | Ненужные общие селекторы или вложенные обработчики |
| Отличается типографика | Лишний `font-weight`, локальный `font-family`/размер текста |

**Перед коммитом:**
1. Найти определения нужных классов и миксинов во всём актуальном `main`.
2. Сверить desktop и mobile, светлую и тёмную темы, `default` и `glass` декор, разные акценты.
3. Открыть popup поверх текста, проверить прокрутку, длинные пункты, при необходимости клавиатуру.
4. Проверить типовые 24px, корректные `vw/dvh`, отсутствие новых `font-weight` и ненужных `!important`.
5. Для SCSS, участвующего в приложении, запустить `npm run build`. После коммита проверить SHA и сборку Vercel.

## 10. Когда обновлять этот документ

Если вводится новый общий миксин, токен темы, постоянное правило оформления или меняется контракт существующего селектора, обновить этот MD вместе с исходниками. Для новых самописных компонентов обновлять также [CUSTOM_COMPONENTS.md](CUSTOM_COMPONENTS.md). Не описывать непроверенную функциональность как уже работающую.

## 11. Иллюстрации SectionArt и кастомизация

Рисованные SVG кнопок Info/Settings используют `SectionArt` и **общий** `src/scss/SectionArt.scss`. Встроенные `.artPaper`/`.artTint`/`.artSolid`/`.artLine` уже подключены к переменным текущей темы. Не создавать отдельную плашку с `background`, бордером и произвольным svg для нового рисунка: в `SectionArt` уже есть фон, декоративные слои и анимационные классы.

`.sectionArt--mini` располагается справа на карточке через `.settingButt:has(> .sectionArt--mini)` с колонкой `8vw` на ПК и `20vw` на мобильном. Дочерняя фигура находится в `Motif` (см. `ArtTheme`), вся оболочка использует `viewBox="0 0 360 176"`. Миниатюра `roadmap` — такой же сюжет в общей оболочке, не отдельная графическая система. Не менять структуру `.settingButt` ради одной темы.

CSS-эффекты `artBob`, `artPulse`, `artShimmer`, `artSway`, `artDraw` применяются только к сюжетным частям. `SectionArt` приостанавливает движение, когда картинка вне viewport. Соблюдать `prefers-reduced-motion`, `pointer-events: none` и общие токены. Подробности — [SVG_ART.md](SVG_ART.md).

## 12. Проверка текста и языков в SCSS

Длинный перевод не должен расширять карточку за ширину экрана. Проверять `min-width: 0`, `overflow-wrap`, `text-overflow`, отступы и выравнивание миниатюры. Не вставлять жёсткую ширину под конкретную русскую фразу, особенно у кнопок Info и FAQ.

У поля `TA` и `AutoDesc` нет ручного resize; автоматическое измерение высоты и/или `field-sizing: content` не должны противоречить `max-height`. Сначала искать декларацию в глобальном и локальном SCSS, а не увеличивать специфичность для исправления.

В `roadmap` используются `--accent_hov`/`--grad_hov` для выделения текущего релиза, `--accent` для линии прошлых релизов и `--borderWh` для будущего. Эти значения динамические, не заменять на фиксированные цвета. Тестировать с EN, RU, светлой/тёмной и glass-темой.
\n## Регрессии, которые нельзя возвращать

- `Blackout` на iOS должен различать движение по вложенной `overflow-y: auto` области и жест закрытия. Если вложенный скролл не на самом верху при `touchstart`, весь этот жест принадлежит скроллу; закрывать нельзя. Проверять фактическое `scrollTop`, а не только `touchmove` и смещение пальца.
- `ContextMenu` открывается после 350 мс **до отпускания**, в каждом контексте подсвечивает пункты по скольжению, на том же исходном элементе остаётся открытым. Меню списков внутри `SideMenu` позиционируется в границах панели. У `SMnav` и `.smHeaderSelected.open` нет бордеров; градиентный фон `accent → grad` **всегда `border: none`**.
- Для выбора фона в настройках использовать текущую страницу `/wallpapers` (`WallpaperStudio`); старую модалку `BackgroundLibrary` сохранять для совместимости с `var(--mc)` и blur, не раскрывать всю библиотеку прямо в `.settingInnerDiv`; управление сохранёнными файлами принадлежит серверу. `BgHandler` — вложенный шаг кадрирования, не самостоятельная галерея.


## Важнейшее правило границ и слоёв

**БОРДЕР ТОЛЬКО У ЭЛЕМЕНТОВ, ЗА КОТОРЫМИ ВИДЕН ФОН ПРИЛОЖЕНИЯ, ЕСЛИ НЕ СКАЗАНО ИНОЕ.**

Внутренние элементы, полностью расположенные на `var(--mc)` или `var(--interact)`, **не получают декоративный border**. Активный фон `linear-gradient(135deg, var(--accent), var(--grad))` всегда имеет `border: none`. Исключение: намеренно обведённые опасные/удаляющие действия (`var(--notValid)`) и явно заказанные пользователем границы. Не добавлять бордер миниатюрам фоновой галереи, `Selector`, `SMnavExtraDiv.chats` или `SMnavExtraDiv.habits`. Вкладки стандартной/пользовательской галереи реализуются **штатным `Selector`**, а не собственной парой кнопок.

## Анимации и скелетоны загрузки

- Для реальной загрузки данных используйте штатный `Skeleton` либо существующие `.skeletonLine`, `.skeletonBlock`, `.skeletonCircle` из `src/scss/Loading.scss`. Не показывайте «Ничего не найдено» до завершения загрузки и не подменяйте загруженный пустой список скелетоном.
- Новые блоки настроек, миниатюры библиотеки и результаты выбора действий могут плавно появляться через `opacity` и небольшое `translate` (200–300 мс), с коротким stagger для первых элементов. Существующие анимации жестов и 320 мс SideMenu не менять.
- В `prefers-reduced-motion: reduce` отключать декоративные анимации/пульсацию и переходы, не отключая функционал и состояния.
- Пользовательские изображения загружать с отдельным скелетоном **до `onLoad`**, затем проявлять изображение через opacity. Ошибки загрузки не должны оставлять бесконечно пульсирующий скелетон.
- Настройки эффектов заднего фона (размытие, движение, фильтры) живут в `settingInnerDiv` раздела «Интерфейс» и используют штатный `SeekBar`, а не собственный ползунок внутри модалки. Выбор фона идёт на `/wallpapers`, дополнительные эффекты доступны через `WallpaperSettings`; совместимая модалка не должна дублировать эффекты.
- Лимит пользовательских фонов — **6** в клиенте, API и ограничении `settings_bg_gallery_max6` в Supabase; новые изображения можно добавлять только при числе меньше шести, существующие не удаляются при обновлении.

## Оформление библиотеки фонов и фильтров

- Старая модалка `BackgroundLibrary` использует сетку в две колонки и штатный `Selector`; основная страница `/wallpapers` использует собственную пятиколоночную сетку, без названий на плитках и с SVG добавления. Не переносить геометрию старой модалки на Studio.
- Раздел «Интерфейс» имеет **один `settingInnerDiv` «Задний фон»**. Сначала текущий фон и кнопка «Изменить фон» (`font-size: 16px`), затем ползунок `SeekBar` с названием «Размытие заднего фона» (без `0px` в заголовке), отдельная строка движения фона и отдельный `settingSpan` «Фильтры».
- Выбранный ч/б фильтр: чёрно-белый градиент; сепия: коричнево-сепийный градиент; негатив: инверсия именно текущего `accent → grad` на псевдоэлементе, чтобы текст остался читаемым. Для всех выбранных фильтров `border: none`.
- У `.contactsUser.active` SVG (в том числе в `PreviewAccent`) должен иметь `color/fill: var(--inner_text)`; не задавать на самой SVG конфликтующее `color="var(--accent_text)"`.
- `Selector` в `Blackout` обрабатывает touch и pointer сам, с `stopPropagation` и `setPointerCapture`, без ожидания и без проверки `dontHandleOther`. Это правило распространяется на все страницы.

## Стоковые фоны, вид и поведение миниатюр

- `BackgroundLibrary` имеет две колонки, штатный `Selector`, исходные `bgMini`, подпись снизу по центру и **один hover**: только лёгкое осветление миниатюры, без отдельного ховера/бордера на обёртке `.bgPick`. Бордер внутри `mc` запрещён, если отдельно не оговорён.

## Стоковые фоны должны зависеть от accent / grad

- **Все новые стандартные фоны** (`art`, `aurora`, `nebula`, `sunset`) обязаны строиться на CSS-переменных `--accent`, `--grad` и `--bgc`. Не задавать фиксированные синие, зелёные, розовые цвета, которые перестанут соответствовать выбранной теме.
- Для паттернов использовать **псевдослучайные, но стабильные** позиции: генератор с фиксированным seed на каждый фон. Превью миниатюры и настоящий фон используют одну и ту же раскладку; не вызывать `Math.random()` на каждом рендере. После изменения accent/grad паттерны должны менять цвета автоматически, но не прыгать.
- Белые полосы и регулярная «звёздная» сетка не подходят: использовать мягкие пятна, туманности, широкие ленты сияния, органические формы и SVG `SectionArt`. Не добавлять декоративные бордеры внутри галереи.
- `habitTabDP` в «Активности → Расписание»: **`border: 1px solid var(--block_border)`**, при `:focus` и `:focus-visible` — `border-color: var(--accent)`, всегда `outline: none`. Не заменять бордер outline, даже если браузер показывает календарь.

## ТРЕТЬЯ ОБЯЗАТЕЛЬНАЯ ПАМЯТКА — HOVER, ГРАДИЕНТ И ЦВЕТ SVG

**НИКОГДА НЕ ОСТАВЛЯТЬ ДЕКОРАТИВНЫЙ BORDER ИЛИ АКЦЕНТНЫЙ SVG НА ГРАДИЕНТЕ — ДАЖЕ ТОЛЬКО ПРИ `:hover`, `:active` ИЛИ `[aria-expanded="true"]`.**

- Проверять **все** состояния элемента: обычное, `:hover`, `:active`, выбранное, открытое (`aria-expanded`), `:focus-visible`, disabled. Если хотя бы в одном состоянии `background: linear-gradient(135deg, var(--accent), var(--grad))`, там обязательны **`border: none`** и **`color: var(--inner_text)` для текста и каждой SVG**. Это правило действует также на вложенные `span`, `path`, `svg` и вложенные компоненты с собственным `color: var(--accent_text)`.
- Акцентный цвет `var(--accent_text)` допустим у иконки **только на нейтральном фоне**, где обеспечен контраст. При появлении градиента даже в hover и active переопределять **вложенную SVG** на `var(--inner_text)` селектором достаточной специфичности. Не полагаться только на `color` родителя: у SVG могут быть собственные правила.
- Если нейтральная кнопка (`background: var(--mc)` или `var(--interact)`) находится **непосредственно поверх видимого фона приложения**, у неё ОБЯЗАТЕЛЬНО `border: 1px solid var(--block_border)` в обычном состоянии. Если градиент появляется только на `:hover`, `:active` или при `[aria-expanded="true"]`, граница убирается **только в этом градиентном состоянии** через `border: none`. НЕ удалять границу из базового состояния из-за наличия градиента на hover. Для активной градиентной поверхности запрещены `border-color`, полупрозрачные линии и декоративный `outline`. Исключения прежние: явно требуемые пользователем границы и специально оформленные опасные действия.
- **БОРДЕР ТОЛЬКО ТАМ, ГДЕ ЗА ЭЛЕМЕНТОМ ВИДЕН ФОН ПРИЛОЖЕНИЯ**, если не оговорено иное. Внутри `var(--mc)`/`var(--interact)` не добавлять его ради украшения. Перед коммитом проверять CSS не только компонента, но и общие hover-правила (например, `.modulesenderInfo:hover`), специфичность и поздние переопределения.

Правильный пример для кнопки поверх видимого фона приложения, со своим акцентным SVG:

```scss
.exampleButt {
    border: 1px solid var(--block_border);
    background: var(--interact);
    color: var(--tc);

    > svg {
        color: var(--accent_text);
    }

    @media (hover: hover) {
        &:hover {
            border: none;
            background: linear-gradient(135deg, var(--accent), var(--grad));
            color: var(--inner_text);

            > svg, span, .nestedIcon > svg {
                color: var(--inner_text);
            }
        }
    }

    @media (hover: none) {
        &:active {
            border: none;
            background: linear-gradient(135deg, var(--accent), var(--grad));
            color: var(--inner_text);

            > svg, span, .nestedIcon > svg {
                color: var(--inner_text);
            }
        }
    }
}
```

### ЧЕТВЁРТАЯ КРИТИЧЕСКАЯ ПРОВЕРКА — ГРАНИЦА МЕНЯЕТСЯ ВМЕСТЕ С ФОНОМ

**НЕЙТРАЛЬНЫЙ `--mc` / `--interact` НА ВИДИМОМ ФОНЕ ПРИЛОЖЕНИЯ → `border: 1px solid var(--block_border)`. ГРАДИЕНТ `accent → grad` НА HOVER / ACTIVE / OPEN → `border: none` И `color: var(--inner_text)` У ТЕКСТА И ВСЕХ SVG.** Не путать это правило с запретом внутренних декоративных границ в уже залитых `--mc` панелях.
