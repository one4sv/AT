# Web Push — клиент

Backend: one4sv/achievetogether-server/docs/WEB_PUSH.md. Клиент применяет Push API и VAPID public key (private key остаётся только на сервере). Корневой Service Worker /at-wallpaper-cache-sw.js обслуживает одновременно push, notificationclick и изображения /wallpapers/*. Дополнительный SW с scope="/" НЕ регистрировать: он вытеснит push-обработчик. API и содержимое чатов не кэшировать. Отключение кэша обоев не должно вызывать unregister и не удаляет push-подписку.

Настройки → Уведомления: статус браузера и кнопки в нижней части settingInnerDiv «Общие». Permission=denied выделен. Браузерное разрешение и push-подписка — разные статусы. Подписка создаётся только по пользовательскому нажатию через Notification.requestPermission + PushManager.subscribe; сохраняется на сервере POST /api/push/subscribe по cookie session. Отключение на этом устройстве вызывает POST /api/push/unsubscribe и PushSubscription.unsubscribe. События и предпочтения all_note/new_mess_note сохраняются в backend; отключённый чат не доставляет push.

iOS 16.4+: manifest.webmanifest display=standalone, добавить через Safari → Поделиться → На экран «Домой» → Добавить, открыть с иконки, нажать разрешение внутри PWA. В обычной вкладке Safari iPhone Push API недоступен. Инструкция в общей Blackout-модалке PushInstallHelp.

Проверка: npm run check:release && npm run build; iPhone Safari/PWA руками (включение, denied, возврат после смены разрешения, получение сообщений с закрытым приложением, переход по тапу). Проверить, что прежний кэш публичных обоев работает включённым/выключенным и что выключение кэша не отписывает от Push. Production Push требует безопасных переменных VAPID на Render; пока их нет, сервер честно сообщает enabled:false. Напоминания по расписанию отдельно, без рекламных рассылок.
