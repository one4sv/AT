# Web Push — клиент

Backend: one4sv/achievetogether-server/docs/WEB_PUSH.md. Клиент применяет Push API и VAPID public key (private key остаётся только на сервере). Корневой Service Worker /at-wallpaper-cache-sw.js обслуживает одновременно push, notificationclick и изображения /wallpapers/*. Дополнительный SW с scope="/" НЕ регистрировать: он вытеснит push-обработчик. API и содержимое чатов не кэшировать. Отключение кэша обоев не должно вызывать unregister и не удаляет push-подписку.

Настройки → Уведомления: отдельного тоглера Push и блока notificationPermissionPanel больше нет. Показывать notificationNoAdvertising всегда и только предупреждения notificationPermissionWarnings при запрете/отсутствии разрешения, отсутствии поддержки или конфигурации и сбоях. Permission=denied выделяется. При permission=default кнопка «Разрешить уведомления» запрашивает разрешение строго из пользовательского нажатия. При permission=granted компонент AutoWebPush автоматически регистрирует/восстанавливает подписку POST /api/push/subscribe после входа в аккаунт и при возвращении к приложению. Пуши не выключаются отдельным переключателем; общие и событийные предпочтения all_note/new_mess_note сохраняются на сервере. Браузерное разрешение невозможно включить программно вопреки выбору пользователя.

iOS 16.4+: manifest.webmanifest display=standalone, добавить через Safari → Поделиться → На экран «Домой» → Добавить, открыть с иконки, нажать разрешение внутри PWA. В обычной вкладке Safari iPhone Push API недоступен. Инструкция в общей Blackout-модалке PushInstallHelp показывается **только на iPhone/iPad вне установленного PWA**; на ПК/Android и внутри установленного PWA кнопку не показывать. Отдельного выключения Push в UI нет; получение сообщений и событий контролируют общие настройки уведомлений.

Проверка: npm run check:release && npm run build; iPhone Safari/PWA руками (включение, denied, возврат после смены разрешения, получение сообщений с закрытым приложением, переход по тапу). Проверить, что прежний кэш публичных обоев работает включённым/выключенным и что выключение кэша не отписывает от Push. Production Push требует безопасных переменных VAPID на Render; без них сервер честно сообщает enabled:false; готовность конфигурации не доказывает успешную доставку. Напоминания по расписанию отдельно, без рекламных рассылок.
