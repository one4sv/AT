## 12.11.2026 — итоговые инварианты по правкам SideMenu и заголовка активности

- **Отступ в SM:** `src/scss/SM/habitsList.scss`, `.habitInfo { margin-left: 5px; }` — один отступ у первой строки (имя/стрик/иконка плана/X/N) и второй строки (периодичность/дата/статус), никакого отдельного смещения только у имени. - **Другой одноимённый класс, заголовок `/habit/:id`:** `src/pages/HabitPage/scss/HabitName.scss`: по прямому указанию пользователя удалена **только** строка `margin-left: .5vw;` из базового `.habitNameText`, без какой-либо замены; коммит [55c91b0](https://github.com/one4sv/AT/commit/55c91b0abd4a0637ec9c12fa8577dc8c8fb6f250). Мобильный `margin-left: 1vw` остался в отдельном `@media` и **не был частью запроса**. Не путать базовый класс заголовка с элементом имени в SM и не менять мобильное правило без отдельного требования.
- **Порядок первой строки:** SVG тега → имя → огонёк со стриком **или** `PathIcon` плана рядом с именем → при наличии закрепление; `X/N` совместной активности — у правой границы **этой же первой строки**, по вертикальному центру; во второй строке периодичность или дата, справа выполнено. Не объединять стрик и прогресс в общий `margin-left:auto`.
- **Режимы приглашений:** `HabitParticipantPicker` в плане должен совпадать по компоненту, CSS и доступным действиям с модалкой активности; серверная связь группы — `one_off_plans.chat_id`. Нельзя повторять регрессию, когда в варианте плана исчезали «Добавить в беседу» и «Создать беседу». Реальные двухаккаунтные сценарии, права/блокировки и iPhone остаются отдельной QA-проверкой.
- **Снятие выполнения в общем списке:** `DoneContext.markDone` обновляет общий календарь; SVG изменения состояния должна обновляться после успеха API, даже если отмеченная активность не является текущей `/habit/:id`. **Удаление habit ID=12 «Сыграл в доту»** агентом не выполнялось; серверный путь `/delete` исправлен и покрыт тестами, но живой результат под аккаунтом владельца надо подтвердить.
- **Правило будущих правок:** буквальный запрос «удалить эту декларацию» означает **удалить без замены**, «как раньше» означает сверить историю и стили, «точь-в-точь как в активности» — переиспользовать компонент, состояния, CSS и backend, а не просто повторить визуальный дизайн. Не перестраивать соседние элементы без задачи. Статические тесты и CI не являются подтверждением внешнего вида или жестов в браузере.
