# Продолжение работы над AchieveTogether

Этот документ описывает текущее состояние и порядок продолжения работы без дневника изменений. Список дат и крупных обновлений ведётся **только в [CHANGELOG.md](CHANGELOG.md)**. Источник истины — актуальный `main`.

## Ключевые принципы

- Перед исправлением читать [AGENTS.md](../AGENTS.md), [CODE_STYLE.md](CODE_STYLE.md), [SCSS_GUIDE.md](SCSS_GUIDE.md) и профильный документ. Сохранять JSX/SCSS, порядок импортов, без новых `font-weight`.
- Жесты SideMenu, ContextMenu и слайдеров не конфликтуют. Long press открывает меню через 350 ms до отпускания; отпускание на исходном элементе оставляет меню открытым, на пункте — выполняет действие, вне — отменяет.
- `React.lazy` маршрутов и Blackout не должен ломать стили. Общие правила в `src/scss/sharedControls.scss`, контролы создания/редактирования активности — `habitFormControls.scss`, хедер активности — `HabitName.scss`. Оформление должно работать при прямой загрузке.
- У `habitMenu` слой выше страничного хедера. У /wallpapers три неизменных значка возможностей заливки, рисунков и освещения, которые видны до открытия настроек и не зависят от переключателей.
- В `/wallpapers` выбор миниатюры только меняет предпросмотр, применение — отдельной кнопкой; пользовательские обои ограничены пятью, поддерживаются фото/анимации/паттерны по правилам [WALLPAPERS.md](WALLPAPERS.md).
- `completion_mode`, `metric_progress_mode`, `schedule_blocks_mode` независимы. `owner` неизменяем; ограничения по вступлению в беседу защищает сервер.

## Открытые проверки

- UI на реальном iPhone Safari, desktop и Android, при входе и без входа.
- Полный E2E совместной активности на двух пользователях, права `owner`, приглашения, realtime, отметки до вступления, личный/общий прогресс, таймер/счётчик/задачи.
- Модалки и стили после прямого открытия URL, устойчивость кадров, загрузка фото, жесты каталога и SideMenu.
- Web Push после закрытия приложения при настроенном серверном VAPID и актуальной подписке.
- Совпадение успешной сборки GitHub Actions с опубликованным production SHA Vercel. Ошибка лимита деплоев либо тест без fixture — не подтверждение работоспособности функции.

**Нельзя закрывать QA по одному `READY`/CI**; проверять наблюдаемое поведение в браузере и фиксировать недоработки в Linear.
