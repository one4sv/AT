# Приёмка и регрессии AchieveTogether

Чек-лист до объявления исправления завершённым. Документ предназначен для разработчиков и агентов. Статус READY/LIVE — **только статус сборки и публикации**, не доказательство, что прошёл реальный сценарий под пользователем.

## Подготовка

1. Прочитать `AGENTS.md`, `CODE_STYLE.md`, `CUSTOM_COMPONENTS.md`, `SCSS_GUIDE.md`, `COLLABORATION_AND_PERMISSIONS.md` и соответствующий функциональный MD.
2. Проверить текущий `main` и фактический SHA на GitHub, Vercel, Render. Не основывать изменения на старых копиях или фиксированных SHA из отчётов.
3. Работать с QA-аккаунтами и их тестовыми активностями **только если есть безопасная возможность вернуть состояние**. Не переименовывать и не изменять реальные пользовательские привычки, беседы, приглашения и их отметки.
4. До выполнения SQL сверить действующую схему и RPC Supabase, настройки RLS и секреты; не повторять миграцию наугад.
5. Собрать client `npm ci` → `npm run build` (`tsc -b && vite build`); для серверного JS проверить `node --check` изменённых файлов и специализированные тесты.

## UI, темы и взаимодействия

- [ ] Desktop и реальный iPhone/Safari; отдельно узкий экран, масштаб страницы, экранная клавиатура.
- [ ] Светлая/тёмная, стеклянная/обычная тема, различные accent/grad; выпадающий `SelectList` на фоне другого текста.
- [ ] Списки, длинные имена, непрерывные ссылки, пустое/загрузочное/ошибочное состояние.
- [ ] Модалки `Blackout`: скролл содержимого, safe-area, нижние кнопки, отсутствие лишнего крестика/«Отмена», полоска свайпа в нужном месте.
- [ ] Контекстное меню: ПКМ, кнопка, long press (350 ms), отпускание/отмена, отсутствие конфликтов с горизонтальными свайпами.
- [ ] `AccInfo` и `GroupInfo`: одинаковая анимация сворачивания 320 ms, прокрутка, переключение вкладок и жесты.
- [ ] Никаких добавленных `font-weight`; отступы и геометрия по стилю AT, основные радиусы 24px.
- [ ] Любой `textarea` расширяется по содержимому без ручного `resize`; при предельной высоте имеет управляемый внутренний скролл. Проверить `TA`, `AutoDesc`, комментарии, описания.

## Совместные активности и беседы

- [ ] Принятие/отказ/повторное приглашение без дублирования и обхода приватности.
- [ ] Пара не принимает третьего участника без перехода в беседу; добавление/отвязка беседы корректны.
- [ ] Личный/общий режим выполнения не смешивает отметки участников.
- [ ] Таймер, счётчик, задачи, день в календаре, статистика, расписание и циклическая периодичность корректны.
- [ ] До `chat_members.joined_at` участник не может выполнить дату: UI и прямой `/markdone`, задачи, таймер. День вступления и даты после — разрешены при нужных правах.
- [ ] Имеющие доступ к комментариям, но не к выполнению, могут комментировать по правилам API.
- [ ] Роль `owner`: 100, 15/15, название/описание/приоритет/права не меняются, назначить owner обычному пользователю/по умолчанию нельзя; проверка прямых API.
- [ ] Смена ролей и разрешений не затрагивает чужие данные и не даёт обхода при блокировке.
- [ ] Realtime отображается у обоих участников, старые данные и статистика не подменяются общими.

## Публикация

- Коммит должен содержать только связанные изменения; перед push проверить diff. По возможности один коммит за рабочий набор.
- Клиент — [Vercel](https://achievetogether.vercel.app/), сервер — Render. Автодеплой из `main`, не запускать второй деплой без причины.
- Проверить, что Vercel `READY` и Render `live` относятся **к последнему SHA**, а не к предыдущему коммиту.
- После публикации проверить URL, страницу и авторизованный сценарий, а не только лог `vite build`.
- В отчёте разделять: «изменено в коде», «собрано», «задеплоено», «проверено вручную/e2e».
- Зафиксировать неготовые сценарии в Linear, не закрывать issue без подтверждения.

## Передача результата

В итоговом отчёте указать пути изменённых файлов, ссылку на коммит и production, результаты проверок, ограничения и следующий незавершённый пункт. Тесты, которые не запускались, явно отметить как **не проверено**.
