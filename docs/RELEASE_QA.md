# Приёмка и регрессии AchieveTogether

Чек-лист до объявления исправления завершённым. Документ предназначен для разработчиков и агентов. Статус READY/LIVE — **только статус сборки и публикации**, не доказательство, что прошёл реальный сценарий под пользователем.

## Подготовка

1. Прочитать `AGENTS.md`, `CODE_STYLE.md`, `CUSTOM_COMPONENTS.md`, `SCSS_GUIDE.md`, `COLLABORATION_AND_PERMISSIONS.md` и соответствующий функциональный MD.
2. Проверить текущий `main` и фактический SHA на GitHub, Vercel, Render. Не основывать изменения на старых копиях или фиксированных SHA из отчётов.
3. Работать с QA-аккаунтами и их тестовыми активностями **только если есть безопасная возможность вернуть состояние**. Не переименовывать и не изменять реальные пользовательские привычки, беседы, приглашения и их отметки.
4. До выполнения SQL сверить действующую схему и RPC Supabase, настройки RLS и секреты; не повторять миграцию наугад.
5. Собрать client `npm ci` → `npm run build` (`tsc -b && vite build`); для серверного JS проверить `node --check` изменённых файлов и специализированные тесты.

### 04.11.2026 — мгновенное оформление фона без статичного кадра

- `settings_bg_effects` хранит весь `BackgroundEffects` (размытие, movement, filter, speed) через штатный `useLocalStorage`, а не `useState` с пустыми значениями.
- Ключ включён в `APPEARANCE_KEYS`: последнее оформление продублировано в `settings_appearance` и доступно до получения пользователя, как accent/grad/bg. Пользовательский ключ `<nick>_settings_bg_effects` отделяет настройки разных аккаунтов.
- Сначала рисуется значение из localStorage; запрос `settings` не должен заменять актуальный локальный кэш устаревшим ответом. Сервер используется для первичной гидратации, когда локального значения нет. `refetchSettings` не должен возвращать фон к дефолтным значениям.
- При первом входе без локального кэша `Background` не рисует промежуточный статичный кадр: ждёт завершения загрузки настроек; при последующих открытиях локальный кэш применяется уже при первом React render.
- Изменение ползунка, фильтра или переключателя мгновенно меняет `bgEffects` в контексте, перерисовывает фон и сохраняется в localStorage; отправка на сервер остаётся с debounce. Проверить reload, медленный сервер, смену аккаунта, ошибку API и 0×.

### 2026-11-04 — исправление обрезания движущихся фонов

- `Background` создаёт **неподвижную** внешнюю рамку `.background` (`overflow:hidden`) и внутренний `.backgroundCanvas` с запасом за экраном `--background-bleed`. Именно внутренний слой получает `filter`, `atBackgroundDrift` и `--scene-duration`, чтобы размытие и перемещение никогда не открывали края контейнера. Не анимировать и не фильтровать внешний clipping frame.
- Запас края зависит от `bgEffects.blur` и не требует повторного запроса API; изменения мгновенно отражаются через `useLocalStorage`. Компонент одинаков для страницы, бокового меню и полноэкранного просмотра. Отдельные SVG-сцены рендерятся внутри `.backgroundCanvas`.
- `.atScenePattern` не обрезает частицы собственным `overflow:hidden`: margin 8% для `atFloat`, margin 24% для вращения `orbit`. Границы сцены остаются в `.atScene`, поэтому фон не вылезает поверх интерфейса.
- QA: проверить движение, blur 0 и 30px, скорости 0/1/3×, все stock-фоны, изображения пользователя, полноэкранный просмотр, SideMenu, узкий viewport и уменьшение движения. Нет резких прямоугольных краёв или открытых полос на любом кадре.

### 04.11.2026 — предпросмотр фоновых сцен, паттерны, переключение движения

- В `BackgroundLibrary` выбор **не** включает `bg_effects.movement` автоматически. Движение включается/выключается только через отдельный `Toggler`; у статичных фонов он передаёт `disable={!supportsBackgroundMotion(bg)}`, визуально сереет, а `SeekBar` скорости тоже заблокирован. Два стабильных seeded набора в `BackIconsScene`: упорядоченный и хаотичный, пересекающийся. Превью и основной фон используют один паттерн.

В раскрываемой панели доступны фильтр, blur, movement, speed и паттерн, но **только в состоянии самого предпросмотра**. Ни `setBgEffects`, ни API `updatesettings` там вызывать нельзя; при выходе всё возвращается к сохранённым параметрам. Круглая кнопка закрытия остаётся снизу по центру в `PageBottom`.

### 2026-11-05 — фоновые сцены, анимация и сворачиваемая библиотека

- Нижняя панель `BackgroundFullscreen` должна содержать две **рядом расположенные по центру** кнопки — круглую «Выйти» и `modulesenderInfo` с настройками/названием. Для обоих элементов устанавливать `pointer-events: auto`; у внешнего `PageBottom` они отключены, поэтому без переопределения плашка перестаёт нажиматься. Размеры и выравнивание проверять на ПК и iPhone.
- `supportsBackgroundMotion` разрешает движение только сценам с реальной управляемой CSS-анимацией. Для `landing`, `default`, `color`, пользовательских картинок и `sunset` переключатель и скорость **disabled**; искусственный `atBackgroundDrift` (zoom/pan) для неподвижных фонов не использовать. Переключение фонов не меняет состояние `movement`.
- В `art` у `SectionArt` есть собственные `artBob/artPulse/artSway/... ` keyframes, которые раньше работали даже при выключенном движении. Внутри `.atScene--art:not(.atScene--running)` явно отключать **все** CSS-анимации вложенных SVG через `animation: none !important`, не затрагивая независимые `SectionArt` на других страницах.
- У «Контурных фигур» паттерн `chaos` располагает 54 SVG в компактной сетке с лёгким перекрытием, небольшим jitter и слабой непрозрачностью. Размер — `settings_contour_size` через `useLocalStorage`.
- У «Рисунков AchieveTogether» отдельные, не общие с контурами настройки `settings_art_pattern` и `settings_art_size` через `useLocalStorage`; отображать общий `ContourPatternPicker` с параметром `subject="art"`. Оба режима и размер 0.5–1.5× должны работать в основной теме и в изолированном `BackgroundFullscreen` (`previewArtPattern` / `previewArtSize`), без записи в пользовательские настройки при предпросмотре.
- В `backgroundCatalog` «Рисунки AchieveTogether» находятся в «Основных». В `BackgroundLibrary` заголовки групп — кнопки с `aria-expanded` и сворачиваемым `hidden` содержимым; у SVG `LayoutGrid` в названиях контуров/рисунков `title` объясняет возможность настройки паттерна.
- Если в кнопке «Изменить фон» миниатюра «Акцентного свечения» становится чёрной, не использовать CSS shorthand `background: var(--bgc)` на `.bgManagePreview`: это затирает `background-image` класса `landingBackground`. Вместо него `background-color`.
- QA (ещё не E2E): переключить каждую категорию в свернутом/раскрытом состоянии, проверить движение off у art после перезагрузки, отключённый тумблер у статичных фонов, настройку обоих паттернов, отсутствие записи из полноэкранного предпросмотра, миниатюру accent glow, нижнюю панель и её кликабельность в Safari iPhone.

### 05.11.2026 — реальный хаос в фоновых SVG

- В `BackIconsScene` режим `order` сохраняет упорядоченную раскладку 54 иконок, а `chaos` создаёт **108 отдельных контурных SVG** с независимыми случайными `x/y` по всей площади, произвольными поворотами, разными размерами и невысокой прозрачностью. Для хаоса **нельзя** рассчитывать координаты от `row`/`column` даже со смещением: тогда снова возникает ровная сетка. Мягкое минимальное расстояние предотвращает отдельные чрезмерно плотные скопления, не выравнивая фигуры по рядам.
- В `BackgroundScene` режим `artPattern="order"` оставляет прежние четыре `SectionArt`. В `chaos` используются **8 разных иллюстраций**, случайно выбранных без повторов из всех 17 поддерживаемых `ArtTheme` (`SectionArt`); каждый экземпляр получает независимые `left/top/width/rotate`, их положение не привязано к фиксированным слотам. Сохраняются `artSize` и выключение внутренних анимаций через `atScene--art:not(.atScene--running)`.
- Случайный seed формируется **один раз при загрузке модуля**, а готовые позиции живут на уровне модуля. Поэтому переключение настроек и перерисовки React не двигают элементы хаотично каждый кадр, миниатюры и полноценный фон показывают **одинаковое** расположение. При следующей перезагрузке страницы композиция меняется.
- QA: «Хаос» должен явно отличаться от сетки на полном экране и в миниатюре, покрывать всю площадь без центрального скопления, контуров заметно больше, чем рисунков. На рисунках убедиться в разных темах `SectionArt` без повторов в одной композиции. Проверить оба режима, `artSize/contourSize`, movement off и reload на ПК/iPhone.

### 05.11.2026 — анимации предпросмотра и галереи

- В `BackgroundFullscreen` панель раскрытия/настроек нельзя удалять из DOM мгновенно при `panelOpen=false`: обернуть в `AnimatePresence`, а `motion.div` задать **и** enter, **и** exit (opacity + небольшое смещение + scale). На `prefers-reduced-motion` время перехода 0.
- Нажатие вне `.backgroundFullscreenPanel` и `.backgroundFullscreenInfo` закрывает раскрытую панель, в том числе на iPhone; кнопки внутри не должны закрываться внешним click-handler.
- Сетка фоновых миниатюр (6/страница) перелистывается с анимацией в сторону жеста: `AnimatePresence mode="wait"` + `motion.div` с направленными enter/exit и `drag="x"`. Горизонтальный жест меняет страницу, вертикальный прокручивает панель. Нельзя допускать синтетический click и случайный выбор после свайпа.
- Основной fullscreen по горизонтальному свайпу/drag (тач на iPhone и мышь на ПК) циклически проходит единый `backgroundCatalog` + все загруженные пользовательские изображения. Навигация не записывает выбор фона в настройки. Стрелки остаются.

Для всех остальных миниатюр зарезервировать `1px solid transparent` и `box-sizing: border-box`, чтобы размер рисунка не менялся при активации и DOM не пересоздавался из-за рамки. Не сочетать градиент и цветную границу.
- QA: открыть/закрыть настройки; нажать вне на iPhone; свайпнуть по сетке и по основному холсту в обе стороны; добраться с последнего стандартного фона до первого пользовательского и обратно; проверить `prefers-reduced-motion` и что активный border не изменяет геометрию миниатюры.
