# Разовые планы AT (dev 0.6.4)

## Граница модели

- Разовый план (\`one_off_plans\`) имеет дату; время необязательно. Не является \`habit_planned\`, не наследует periodicity/стрики. Цели отнесены к dev 0.6.5, ONE4SV-16.
- План personal/shared; у совместного создатель выбирает режим выполнения personal/shared. После первой отметки смена режима запрещена. В общем режиме отметку на первом этапе меняет владелец; индивидуальное выполнение участник ставит себе.
- У одного пользователя может быть несколько планов на дату. Планы могут быть связаны с несколькими чатами через отдельную таблицу (UI позже). Членство в чате не даёт автоматически право просматривать приватный план.
- Планы приватны по умолчанию. Сервер проверяет сессию и членство на каждом ресурсе. \`anon\`/\`authenticated\` не получают прямого доступа к таблицам; запросы делает серверный service role.

## Текущий первый этап (опубликован в main)

- Сервер: \`database/one_off_plans_20261111.sql\`, \`routes/plans/plans.js\`: \`GET/POST /plans\`, \`GET/PATCH/DELETE /plans/:id\`, \`POST /plans/:id/complete\`, \`/cancel\`, \`/invite\`, \`/respond\`. Приглашение пока только существующему незаблокированному личному контакту; самостоятельное вступление и исключения планов пока не реализованы.
- Клиент: `PlansContext` не пересекается с `PlannedContext` (планирование дней активностей); обзор `/habit` 1:2:1, детальная `/plan/:id`, создание через модалку `AddPlan`. Страница `/plan/new` удалена. Отдельная активность `/habit/:habitId` не меняется.
- Сетевые запросы \`api\` идут через /api; все UI-строки — common.plans в RU/EN.
- Первый этап опубликован в `main` 11.11.2026. Клиентский CI (`tsc`, Vite и Chromium smoke) прошёл, Vercel для SHA `0e64cbd` — `READY`; серверный CI прошёл, Render для SHA `67ce338` — `live`. Миграция `one_off_plans_20261111` применена в Supabase, прямой доступ `anon`/`authenticated` закрыт. **Авторизованные E2E с двумя пользователями и iOS не подтверждены**. ONE4SV-79 остаётся In Progress.

## Дальнейшие этапы (всё в ONE4SV-79)

1. Настройки приватности: будущие/прошедшие планы, исключения, приглашения и правила самостоятельного присоединения.
2. Активности/планы в Acc, контекст чатов и несколько бесед на план; пост-приглашение с явным согласием владельца, необязательная связь с активностью.
3. Push-напоминания с отменой/переносом, вложения, чек-листы, журнал событий, посты о плане, архив.
4. Серверное агрегационное API и UI даты/обзора. Не раскрывать приватный план через прямой URL, поиск, профиль, чат, Push или старый пост.

## Проверка

- Owner, accepted, pending, non-member, blocked contact, changed auth version, canceled plan.
- Personal/shared completion, два разных участника и X/N, смена режима после отметки.
- Без времени, с началом/концом, перенос даты, error responses и повторный запрос.
- Приватность и независимость от привычек, отсутствие конфликтов жестов Selector, Acc и календаря.


## Обзор и модалка: 11.11.2026

- Обзор `/habit` ограничен по высоте 40dvh на ПК (как StatsDivHabit); центр прокручивает только содержимое, левый календарь и правая колонка не вытягиваются. На мобильных центр имеет 50dvh и собственный скролл.
- Заголовок центра отображает выбранную дату из `CalendarContext` через `formatDateLabel`. Внутренняя дата `ChosenDay` скрывается только в обзоре через `showDate={false}`; детальная активность сохраняет прежнюю разметку.
- Кнопка `+` открывает штатное контекстное меню `planCreate` с действиями «Новый план» и «Новая активность». Новая активность использует существующий `AddHabit`.
- «Новый план» — модалка `AddPlan` через `Blackout`/`ModuleMap`, а не `/plan/new`. Переиспользуется `PlanEditor` с оформлением/контролами `AddHabit`; начальная дата — выбранный день. Создание закрывает модалку лишь при успехе API.
- Пустое состояние списка планов — `SectionArt theme="plans"` с SVG календаря/часов.
- Обзор, модалка, серверный API и новые таблицы доставлены в production из `main` по запросу владельца. До начала проверок записей планов — 0. Несмотря на зелёный CI, реальный авторизованный E2E создания/выполнения в браузере ещё не проверен.

## 11.11.2026 — напоминания о планах

- Общий переключатель `/settings/notifications` «Получать напоминания о планах»: выключен по умолчанию, независим от напоминаний активностей. По умолчанию за 60 минут до начала, варианты момент начала/за 10 минут/1 час/день. План без start_time считается начинающимся в 09:00 в собственной timezone. Web Push подписка обязательна.
- `/plan/:id` содержит раскрывающийся блок «Напоминания»: до 8 дополнительных личных правил на конкретный план (10 минут, 1 час, день, произвольные 1..10080 минут). Правила доступны создателю и допущенным участникам, не влияют на других участников.
- Сервер `at_plan_reminder_*`: отдельные закрытые таблицы и cron/worker, проверки членства и настроек перед отправкой; перенос/отмена плана останавливает старые уведомления. Обновление правил идемпотентное и транзакционное.


### 11.11.2026 — загрузка и навигация

PlansProvider загружает планы после входа или смены аккаунта, сбрасывая старые данные. Фильтры дат SideMenu учитывают планы даже без привычек. Из плана ссылка на настройки уведомлений ведёт на /settings/notes. В «Итоги дня» следующее событие сначала выбирается среди текущих активных временных интервалов. Описание раздела «Активности» в настройках больше не упоминает порядок отображения.
