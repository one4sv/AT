# Команды и подсказки в «Избранном» (AT 0.6+)

## Этап 1 — встроенные поля команд /act и /plan (22.11.2026)

В собственном «Избранном» клавиша `/` и кнопка рядом с эмодзи показывают **один** `EntitySuggestionList` (универсальный React picker для будущих пользователей, планов, активностей и прочих типов). Источник визуальной поверхности списка — `var(--mc)`, `backdrop-filter: blur(6px)`; SCSS: `src/scss/entitySuggestionList.scss`. При вводе обычного текста список не показывается. Placeholder сокращён до «Текст, заметка или /» (EN: «Text, note or /»), чтобы не растягивать TA на телефоне.

Команда `/act` или `/plan` **НЕ открывает модалку**. Наведение мышью показывает preview шаблона без изменения основного текста; нажатие на элемент или Enter в списке фиксирует выбор и заменяет TA **внутри штатного chatWriteBar** на `QuickCommandComposer` (`src/pages/Chat/components/ChatTa/QuickCommandComposer.tsx`). Внешние размеры, границы, шрифт и оформление берутся от текущего TA, без второй отдельной панели; названия команды и полей подсвечены `var(--accent_highlight)`.

Порядок `/act`: название, описание, периодичность (штатный SelectList), опциональные параметры недель/цикла, время начала, время конца. `/plan`: название, описание, дата, начало, конец. Период по умолчанию ежедневный. Для недельного варианта номера дней: `1,3,5` (пн, ср, пт; вс = 0). Для цикла нужны обе длительности. Тег пока автоматически не назначается — `tag: null`, но поле предусмотрено в типе draft.

**Клавиатура:** Enter без модификаторов переходит к следующему видимому полю; Enter на последнем запускает создание и отправку сообщения; Backspace в пустом поле возвращает фокус к предыдущему; Backspace в пустом поле названия или Escape отменяет команду. На сенсорном устройстве поля редактируются обычной клавиатурой и нативным выбором даты/времени, итог отправляется также обычной кнопкой отправки чата. Во время запроса поля блокируются от повторного сохранения.

Клиент использует действующие backend API `POST /plans` (создание личного плана) и `POST /addhabit` (активность), контексты `PlansContext` / `HabitsContext`. `/addhabit` теперь возвращает `habit_id` вместе с прежним `success: true` — аддитивное изменение в `one4sv/achievetogether-server`. По завершении создания отправляется **обычное сообщение самому себе**, состоящее из статуса `План создан` / `Активность создана` (с локализацией) и канонической ссылки на объект. Команды `/act` и `/plan` в историю не отправляются. `Message` распознаёт только строго определённый двухстрочный формат в **собственном** чате и отображает `CreatedEntityCard` с тегом, названием и временем, в стиле `HabitInvitation` **без кнопок принятия**. Данные карточки читаются через уже существующие защищённые `GET /plans/:id` и `GET /habits/:id`; при отсутствии доступа показывается только ссылка с общим заголовком.

Если создание прошло, а отправка карточки не удалась, редактор хранит созданный ID и повторно пытается отправить **только сообщение**, не создавая второй объект; поле временно блокируется. При переходе в другой чат состояние ввода обнуляется. План/активность считаются созданными только при успешном ответе API; намеренного участия в чужих беседах или изменения прав нет. Существующие модалки AddHabit/AddPlan остаются для штатных кнопок и для **автоподсказок из обычного текста** (этап 2), их API не меняются.

Документация: `SCSS_GUIDE.md`, `CUSTOM_COMPONENTS.md`, `SVG_ART.md`, `GESTURES.md`. Критический QA: Enter/Backspace и переходы, выбор периодичности, корректность дат/времени, iOS PWA, длинное описание и мобильная клавиатура, одновременная отправка, ошибка API, отсутствие дублей, карточка после перезагрузки и удаление объекта. Реальное создание не выполнять под пользовательским аккаунтом без отдельной договорённости, тестировать на изолированной QA-сессии.

## Этап 2 — распознавание заметок в «Избранном» (21.11.2026)

Клиентский `src/components/ts/utils/savedMessageSuggestion.ts` распознаёт:
- `31.12 12.00 врач` → разовый план с названием, датой и временем;
- `каждый день работа с 12 до 19` → ежедневная активность с периодом;
- `2 марта др кента` → план, только когда 2 марта ещё впереди в текущем году. Прошедшую дату не переносить автоматически в следующий год; для 2027 года вводить `2 марта 2027 др кента`.

Разбор работает локально, без AI или новых запросов на сервер. `Chat.tsx` выбирает только последнее подтверждённое собственное сообщение в self-chat. Старые, чужие, системные, отредактированные, пересланные сообщения и сообщения с файлами не получают подсказку. При следующем сообщении прежняя подсказка исчезает.

Сравнивать дату с `todayStrFunc()`, а часы с `clockInAppZone()` — учитывается выбранный часовой пояс AT. Ошибочные и прошедшие планы игнорировать. Кликабельная подсветка `var(--accent_highlight)` открывает стандартный `Blackout → AddHabit/AddPlan` с `commandDraft`; не создавать сущность до сохранения в модалке. Повторное нажатие на тот же подсвеченный фрагмент снова открывает модалку, пока сообщение остаётся последним.

В «Настройки → Чаты → Избранное» переключатель `chat_saved_suggestions` реализован через `useLocalStorage`: настройка по аккаунту и устройству, включена по умолчанию. Отключает только автоподсказки; команды `/act` и `/plan` остаются.

Покрытие: `tests/saved-message-suggestions.test.mjs` (прошедшие/будущие даты, повторяемые активности, RU/EN и ложные срабатывания), GitHub Actions и TypeScript build. Unit-тесты не подтверждают реальное сохранение через модалку.

## Коррекция 22.11.2026 — повторное открытие и портал тега

- Умная подсказка последнего сообщения в «Избранном» больше не помечается как одноразово использованная: при повторном нажатии на подсвеченный текст открывается та же штатная `AddPlan` / `AddHabit` со свежими полями. После отправки следующего сообщения прежняя подсказка исчезает, как и раньше.
- Пункт `TagSelector`, открытый из `AddPlan`, может находиться в `document.body` из-за `createPortal`. `Blackout` не рассматривает нажатие на `.planTagPortal` как внешний клик, поэтому модалка остаётся открытой при выборе тега. Настоящие клики вне модалки по-прежнему закрывают её.
- Кнопка `/` должна сохранять фокус textarea на телефоне; ввод `/act ` или `/plan ` (команда плюс пробел) запускает встроенный редактор. Эти два исправления были добавлены в актуальный код и покрыты unit-тестом парсера; реальный iOS Safari требует дополнительной проверки.

## 22.11.2026 — компактный ввод без рамок

В `QuickCommandComposer` вместо полноширинных `input`, `type=time`, `type=date` и крупного `SelectList` используются **одинаковые встроенные `textarea`** рядом с названиями полей: `Название: [текст]`, `Описание: [текст]`, `Периодичность: [текст]`, `Дата: [текст]`, `Начало: [текст]`, `Конец: [текст]`. Названия выделены `var(--accent_highlight)`. Это не rich text редактор и не новая модалка; в той же поверхности `chatWriteBar` сохраняется существующая логика создания и отправки карточки.

Пустое текстовое поле стартует с `width: 1px` и расширяется по ширине содержимого, вычисляемого невидимым `span.chatQuickMeasure` (`ResizeObserver` учитывает смену ширины в мобильном/ПК интерфейсе). Длинный текст переносится, высота `textarea` увеличивается автоматически; `resize: none`. Нажатие на подсвеченную подпись переводит фокус в соответствующее поле. Крестик закрытия `chatSlashButton.quickActive` теперь у правой кромки формы.

Enter без Shift переходит к следующему `textarea`, Enter на последнем вызывает штатную операцию создания, Backspace из пустого поля возвращает к предыдущему с курсором в конце; из пустого названия отменяет команду. Shift+Enter оставляет перенос в описании. Имена/описание/периодичность/дата/время подставляются в тот же `QuickCommandDraft`; нельзя отправлять ошибочные текстовые времена/периодичность. Для периодичности поддержаны RU/EN варианты «каждый день», «несколько дней в неделю», «циклическая», «иногда»; для даты `22.11.2026`/`2026-11-22`; времени `9`, `12:30`, `12.30`. Для `weekly` и `cycle` появляются дополнительные такие же поля. Два отсутствовавших переводных ключа `chatUi.quickCommands.startShort` и `endShort` добавлены и в RU, и в EN.

Исходники: `src/pages/Chat/components/ChatTa/QuickCommandComposer.tsx`, `src/pages/Chat/scss/chatTa.scss`, `src/components/ts/utils/quickCreateCommand.ts`; тесты парсинга `tests/quick-create-command.test.mjs`. Отдельно проверить мобильную клавиатуру и редактирование многословного текста; компиляция не равна E2E.


Дополнение к компактной раскладке: все `InlineQuickField` идут **единым переносимым потоком текста** в `.chatQuickFields` (flex-wrap), а не раздельными широкими рядами. Измеритель ограничивает поле доступной шириной общего редактора; по мере ввода поле увеличивается и соседние поля переходят на следующую строку. Длинное значение переносится в собственной textarea.

## 22.11.2026 — этапы 4–6: @mentions, ссылки на сущности, поиск SM, уведомления

### Упоминания и slash в обычном чате

`ChatTextArea` выбирает только членов текущей беседы для `@nick` через общий `EntitySuggestionList`. Стрелки вверх/вниз, Enter, Escape, касание и возвращение фокуса поддерживаются без второго UI. Текст упоминания вставляется в обычное сообщение; сервер `utils/mentions.js` повторно разрешает ник среди действительных незаблокированных `chat_members` и исключает автора, не принимает переданный клиентом ID как факт. Упоминание постороннего пользователя не создаёт push.

`/habit`, `/plan`, `/post`, `/user`, `/group` запускают существующий picker поиска с debounce и выбирают сущность. После выбора `ChatTextArea` хранит `linkedEntity: { type, id }` отдельно от текста и показывает компактный черновик карточки; после отправки сервер сохраняет `messages.entity_type/entity_id`. Доставка и повторная отправка включают эти поля, а `SharedEntityCard` загружает название через защищённый `GET /chat/entity/:kind/:id` — после переименования название обновится. Если получателю недоступен объект, вместо имени показывается нейтральное сообщение; ссылки в карточке не обходят ACL. Для пользовательской ссылки UUID используется вместо ника. Сервер проверяет право отправителя при `POST /chat` до вставки.

`/invite` предлагает активности и планы из защищённого поиска и ведёт к существующей модалке `HabitParticipantPicker` (через `?invite=1` после загрузки страницы) при наличии полномочий. Она создаёт реальные приглашения через существующий серверный маршрут, не через отправку карточки. `/group` открывает существующий `CreateChat` с `point: InviteUser` на выбранной группе; перед открытием проверяются текущие `my_perms.can_invite_users`, затем сам сервер повторно проверяет право при генерации ссылки и приглашении людей. Команда не создаёт и не отправляет приглашение без действий пользователя. Не переиспользовать `SharedEntityCard` как `HabitInvitation` и не называть ссылку приглашением.

### Поиск в SideMenu

`GET /search/global?q=&page=` на сервере ищет сообщения, комментарии, посты, пользователей, активности, планы и группы с проверкой членства, блокировок и приватности каждого результата. В SideMenu `SMGlobalSearch` использует единый запрос, debounce 250 мс, AbortController, кнопку следующей страницы. Фильтры `/ms`, `/com`, `/post`, `/user`, `/habit`, `/plan`, `/group`, `/new`, `/every` — серверные; `/setting` работает через `useSearchableSettings` локально. Дополнительное меню SMnav в режиме поиска переключает фильтры вместо действий создания/выхода. Сообщения переходят в беседу с `?message=id`, используется существующий `scrollToMessage`; комментарии — `/post/:id#comment-id`. Первичный серверный поиск ограничен доступными и/или членскими сущностями; индексирование всего контента, улучшения пагинации для больших результатов и авторизованный E2E ещё не считаются завершёнными.

### Уведомления

`settings.mentions_note` — отдельная серверная настройка (миграция применена) и переключатель в `NotificationsTab`, `new_mess_note` остаётся обычными уведомлениями чатов. При `all_note=true` упомянутый участник с `mentions_note=true` получает push даже если `chat_members.note=false` или `new_mess_note=false`; при `all_note=false` push запрещён. Сервер доставляет событие `NEW_MESSAGE` по WebSocket всем допущенным участникам даже в mute. Серые счётчики непрочитанных используются у mute-контактов; общий счётчик SMnav серый, если все непрочитанные беседы заглушены. Реальный push на двух устройствах, долгие запросы и iOS QA остаются открытыми.


### 22.11.2026 — тип карточки в черновике и геометрия одиночного медиа

В `ChatTextArea` заголовок выбранной карточки теперь зависит от `linkedEntity.type`: «Пользователь», «Активность», «План», «Публикация», «Беседа» (в EN: User, Activity, Plan, Post, Chat). Вместо общего `shareSelected` используется `chatUi.shareType.*` в двух словарях. У `.chatSharedEntityDraft` ограничены ширина и внутренние отступы; `.answer` не наследует 100% ширины и высоты стандартного ответа, не подсвечивается hover, название обрезается с ellipsis вместо выхода за край скруглений. Крестик остаётся штатным.

У обычных медиа-сообщений без подписи сохраняется класс `mediaOnly`: фон сообщения отсутствует, время/галочки/реакции остаются на оверлее. Для одного изображения/файла новый `singleMedia` убирает принудительную ширину 40vw и позволяет пузырю принять реальную ширину изображения с максимальными ограничениями. Несколько вложений продолжают отображаться сеткой без изменения ширины. Ответ с одной фотографией без своего текста тоже остаётся `mediaOnly`, цитата показывается отдельным компактным оверлеем над изображением; фото с подписью остаётся обычным сообщением. Проверить браузеры desktop/iOS и загрузку изображений в режиме экономии трафика.


### 22.11.2026 — UI отправленных сущностей и команды в обычных чатах

Карточки с entity_type/entity_id без пользовательской подписи используют entityOnly: без внешнего пузыря, ширина по содержимому, метаданные отдельной прозрачной строкой. SharedEntityCard не наследует HabitInvitation и не использует mc: пользователь — имя, @nick и компактный аватар, активности и планы — настоящие иконки тегов, переведённая периодичность/дата/время, пост — автор, фрагмент текста и кнопка открытия. При наличии текста обычный фон сообщения сохранён. Приватность остаётся под контролем GET /chat/entity и ACL.

Список сущностей появляется уже после ввода /habit, /plan, /user, /post или /group без дополнительной буквы; /invite показывает доступные планы/активности. В личном чате /group и /invite используют получателя текущей беседы и ConfirmAction для явного подтверждения, без перехода на другую страницу. В групповом чате автоматического приглашения без выбора адресата нет. Внешний @nick доступен в поиске как карточка пользователя без mention push; существующий участник по @ остаётся настоящим упоминанием. В SideMenu последняя карточка подписывается типом, а не «Пересланное сообщение». Проверить Chrome/iOS и двух авторизованных пользователей вручную.


### 22.11.2026 — улучшение sharedEntityCard

Карточка ссылочного объекта показывает скелетон до загрузки метаданных через защищённый API. Левый отступ уменьшен, автор карточки поста ведёт на страницу аккаунта (nick возвращается сервером), текстовый excerpt увеличен до 700 символов на сервере и 8 строк на клиенте.
