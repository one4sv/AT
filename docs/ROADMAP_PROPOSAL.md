# Roadmap внутри AchieveTogether — проектирование

Референс — [Miro Updates RoadMap](https://miro.com/app/board/uXjVGNsgP9E=/), на присланном скриншоте горизонтальная шкала версий и дорожки задач. **Это визуальный референс:** объекты Miro через API не импортированы; содержимое доски не подтверждено полностью.

## Предложение MVP
- Раздел `/roadmap` и ссылка из информации AT, доступность для гостей.
- Desktop: горизонтальные версии 0.5.x → 0.6.x, дорожки «чаты, активности, посты, дизайн, инфраструктура», карточки целей/исправлений и статус.
- Mobile: вертикальный список по релизам, без необходимости зумить огромную доску.
- Модель: `{id,title,description,version,lane,status,issueUrl,order}`; статусы planned/in_progress/testing/done; фильтры по версии/статусу.
- Источник истины — [проект AchieveTogether в Linear](https://linear.app/atone4sv/project/achievetogether-14167c69bf4a). На первом этапе backend JSON/cache, затем односторонняя синхронизация статусов; не раскрывать токены в клиентском JS.
- Карточка раскрывает детали, ссылку на Linear/GitHub, отметку «Планируется» или «Готово». Никаких выдуманных дат релизов.
- Редактирование публичного roadmap в AT и двустороннюю синхронизацию с Miro/Linear делать отдельной задачей после авторизации, контроля прав и аудита.

## Нужные проверки
1. Согласовать версии и дорожки по оригиналу Miro и Linear.
2. Убедиться, что доска Miro доступна для экспорта: у текущей интеграции ChatGPT нет подключения к ней; для Miro REST API нужны OAuth и `boards:read`/`boards:write`.
3. Протестировать загрузку сотен карточек, длинные заголовки, темы, клавиатуру, мобильный скролл.
4. Разделить реальные реализованные задачи и перспективные идеи, не объявлять roadmap действующим до публикации.
