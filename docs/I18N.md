# Локализация AT: русский и английский

Источник истины: `src/i18n/i18n.ts`, `src/i18n/locales/{ru,en}/*.json`, `src/pages/Settings/Language.tsx` и контексты настроек. Документ описывает **существующую частичную локализацию**, а не утверждает, что все страницы переведены.

## Как сейчас работает язык

- Стек: `i18next`, `react-i18next`, `initReactI18next`.
- Подключение: `src/main.tsx` импортирует `src/i18n/i18n.ts` до рендера React.
- Языки: `ru` и `en`; начальный `lng: "ru"`, `fallbackLng: "en"`, `defaultNS: "common"`.
- Пространства имён: `common`, `sign`, `info`, `settings`, `acc`. Для **каждого** есть одноимённые JSON в обеих папках.
- Текущий язык читается из `SettingsContext`, через `useLocalStorage("settings_lang", "ru")`. Эффект вызывает `i18n.changeLanguage(lang)` и обновляет `document.documentElement.lang`.
- UI смены языка: `/settings/language`, компонент `Language.tsx`, обработчик `setNewLang` из `UpdateSettingsContext`. Не создавать второй независимый selector или язык только внутри одной страницы.
- Не предполагать, что `package.json.version` равен маркетинговой метке: в разделе «О проекте» отображается `dev 0.6.2`.

## Правильный способ переводить новые функции

1. Выбрать существующий namespace по смыслу. `info` — Info/FAQ/roadmap, `acc` — профиль/публикации, `settings` — настройки, `sign` — регистрация, `common` — общие строки.
2. Добавить **одинаковые ключи** в `src/i18n/locales/ru/<namespace>.json` и `en/<namespace>.json`. Менять оба файла в одном коммите.
3. Использовать `const { t } = useTranslation("info");` и `t("roadmap.title")`. Для чисел, вставок и параметров использовать интерполяцию i18next вместо конкатенации.
4. Для переключаемых React-ссылок использовать `<Link to="...">` в JSX, а переводимые части строки — отдельные ключи или `Trans`, не вставлять в JSON HTML и не строить ссылку из пользовательского текста.
5. Для условного выбора языка в **данных**, например `roadmapData.ts`, применён тип `RoadmapText = { ru: string; en: string }` и `i18n.resolvedLanguage?.startsWith("en") ? "en" : "ru"`. Это исключение существующего data-модуля, а **не** разрешение рассыпать `en ? "..." : "..."` по компонентам.
6. Пересмотреть перенос строк, пробелы у ссылок, длинные английские фразы, доступные имена иконок/кнопок и мобильную ширину.
7. Изменив FAQ, проверить ссылки `/info/contacts` и `/info/roadmap` на обоих языках.

```tsx
import { useTranslation } from "react-i18next";
import { Link } from "react-router-dom";

export default function MyInfoLink() {
    const { t } = useTranslation("info");

    return (
        <Link to="/info/roadmap">
            {t("info.roadmap.name")}
        </Link>
    );
}
```

## Особенности текущего FAQ и roadmap

- `src/pages/Info/tabs/FaqTab.tsx`: вопросы `faq.q1`–`faq.q20`, ответы `faq.a*`; для ответов со ссылками сейчас заданы `a9Start/End`, `a10Start/End`, `a19Start/End`, `a20Start/End`. Ссылки вставляет JSX. Если добавлять очередную ссылку, сохранить эту логику либо аккуратно перевести её на `Trans`; не оставлять рядом обычную и кликабельную копии одного ответа.
- `src/pages/Info/roadmapData.ts` хранит двуязычные объекты `features`/`title`/`notice`. У патч-версий `0.x.x` собственных имён нет; заголовки есть у крупных `0.x`. Текущая версия — `dev 0.6.2` без отдельного названия, `0.6` — крупный этап «Эра сотрудничества», будущая `0.7` — «Споты»/«Spots», отдельная очередь `0.6+`. Сначала новые версии, прошлое по умолчанию свернуто.
- В `src/pages/Info/tabs/AboutTab.tsx` версия `dev 0.6.2` — ссылка на `/info/roadmap`.
- Любая информация о планируемых возможностях должна быть помечена как план, а не доступная функция.

## Консистентность формата

- Ключи в JSON сохранять в принятой структуре (например, `info.roadmap.desc`). Не менять существующие имена ключей без обновления всех вызовов.
- Русский и английский тексты должны передавать одинаковый смысл, не обязательно быть дословным переводом.
- Локализовать заголовки, сообщения об ошибке, aria-label, пустые состояния и кнопки; значения API (`personal`, `shared`, `owner`) **не переводить**.
- Русские имена собственных системных ролей, подписи «Без роли» и английские технические идентификаторы различать.
- Не использовать `t` вне React/инициализации без понимания контекста и жизненного цикла языка; для асинхронных уведомлений получать актуальный `t`.
- В юридических текстах `info.json` любое содержательное изменение согласовывать, не переписывать договор или политику ради косметического перевода.

## Проверка языков

- Открыть `/settings/language`, переключить RU → EN → RU, перезагрузить страницу: выбранный язык должен сохраниться.
- Пройти `/sign`, `/info`, `/info/faq`, `/info/roadmap`, `/info/contacts`, `/settings`, `/acc` и экран публикации. Если часть UI всё ещё зашита на русском, записать как **долг локализации**, не объявлять покрытие 100%.
- Проверить вывод ключей `faq.a19Start` в связке со ссылкой, длину заголовков и скролл на iPhone Safari.
- После TSX/JSON-изменений запускать `npm run build`. Для JSON дополнительно проверить парсинг и **симметрию ключей** двух языков; менять ключи одновременно.

### 05.11.2026 — Roadmap: неизменяемые английские названия и содержание

- Названия версий — **только английские, без языковых вариантов и переводов**. Тип данных `RoadmapRelease.title` — одна строка, не `RoadmapText`. Основные: Foundation, Act, Dialogue, Firework, Aphrodite, Affinity, The Castle; текущая 0.6.2 — New Palette. Сами пункты релизов **переводятся**, в том числе «Личные чаты» / “Private chats”. Не дублировать русский текст в поле `en`.
- Отдельная цветная финальная точка исторической шкалы — «Начало» / “Beginning”, дата **14.07.2025**, вне нумерации версий. Дата предоставлена пользователем и не должна выдаваться за дату первого GitHub-коммита.
- Содержание Info собирается из `h1/h2/h3` внутри `.settingTab`. Поэтому основные `0.x` **должны присутствовать в DOM даже при свёрнутой истории**, внутри `.roadmapPastContent[hidden]`; по нажатию пункта содержания история сначала раскрывается событием `roadmap-open-history`, затем выполняется прокрутка. Не удалять историю из DOM условным `showPast &&`.
- В SMheader, SMnav и AccountList все видимые подписи меню и уведомлений должны использовать `t(...)` namespace `common`; фильтры в SideMenuContext также используют локализацию. При добавлении русского UI-текста сразу добавлять англоязычный вариант.

## Имена версий (сверено 06.11.2026)

Имена релизов никогда не переводятся: `0.0 The Beginning`, `0.1 The Foundation`, `0.2 Act`, `0.3 Dialogue`, `0.4 Firework`, `0.5 Aphrodite`, `0.6 Affinity`, `0.6.2 The New Palette`, `0.7 The Castle`. Не использовать `t("roadmap.beginning")` для названия `0.0`. Артикль — часть постоянного английского имени. Подписи функций и описания релизов переводятся через RU/EN как обычно.

### 05.11.2026 — переводы SideMenu, системных сообщений и HabitPage

- `Contact.tsx` и `ContactsList.tsx` берут подписи «Избранное», «Обновить» из `common`; текст превью системного сообщения также проходит через общий форматтер.
- Серверные исторические сообщения сохраняются как русские шаблоны (например, `добавил {} в беседу`). `src/pages/Chat/utils/localizeSystemMessage.ts` переводит **только известные системные шаблоны** непосредственно при отображении в `SystemMessage.tsx` и в превью `Contact.tsx`, сохраняя маркер `{}` для кликабельного пользователя. Не переводить сообщения обычных пользователей, не перезаписывать БД и не интерполировать произвольный пользовательский контент как ключ.
- `HabitPage` использует `common.habitPageUi` и существующие `habitUi`, `habitDialog`, `statsUi`. Покрыты расписание, календарные даты, кнопки выполнения, задачи, комментарии и лента событий, таймер, счётчик, статусы стрика и графики. Дни недели и месяцы форматировать локалью, не жёсткими массивами RU.
- Слова для русского склонения `streak.days_one`/`_few`/`_many` и английского `days_one`/`_other` отличаются по правилам i18next. Скрипт `check-release.mjs` сравнивает такие ключи как одну plural-группу; пропуск целой группы считается ошибкой.
- Повторно проверять все вложенные модалки/меню и ошибки, приходящие текстом с backend: неизвестные шаблоны оставляются как исходные данные. Наличие ключей не заменяет RU/EN тест с реальным аккаунтом.

## Локальный режим бокового меню и кроссплатформенная справка

- `personalization.sideMenu`, `sideMenuAlways`, `sideMenuButton`, `sideMenuMobileHint` находятся в словарях `settings` RU/EN. Не использовать встроенные русские строки в настройке SideMenu или поиске настроек.
- На ПК меню бывает закреплено постоянно или доступно по кнопке; предпочтение `settings_layout` сохраняется через `useLocalStorage` локально для данного браузера/пользователя.
- На телефоне вместо выбора несуществующего постоянного режима показывается переведённое объяснение, при этом меню доступно через кнопку и жест.
- На ПК у обоев остаются SVG с hover-подсказками, на сенсорных устройствах то же описание открывается кнопкой `?` в библиотеке и в выборе обоев предпросмотра.
    
## 05.11.2026 — справка по обоям

Заголовок, описания, пояснения и кнопка закрытия `BackgroundHelp` используют `settings.backgroundLibrary.help*`. Для сообщений справки обязательно показывать переведённую фразу, а не путь ключа. `useBackgroundHelpText` задаёт явный `defaultValue` из соответствующего RU/EN словаря, если активный ресурс i18next не содержит ключа. В E2E проверять, что содержимое модалки не содержит `backgroundLibrary.`. Возможен временный смешанный клиентский кэш после неполного деплоя; корректная сборка должна содержать оба словаря.


## Подписи текущего редактора обоев

- Тексты версий (английские имена релизов) не переводятся; UI редактора, справка и действия локализуются RU/EN.

## 07.11.2026 — числительные в статусах Chat

Для `common.chatUi` в RU/EN добавлены стандартные i18next plural-формы для количества участников, пересланных и выбранных сообщений, закреплений, результатов поиска и минут последнего посещения.
