# Производительность AchieveTogether

Замер baseline: GitHub Actions [42406485887](https://github.com/one4sv/AT/actions/runs/42406485887) до оптимизации: один `index-DbkiwqXd.js` **2865,35 КБ**, gzip **840,03 КБ**; CSS `index-2Mf-d2ah.css` **408,18 КБ**, gzip **64,76 КБ**. Это размеры выходных файлов Vite, не замер реальной загрузки сети.

## Загрузка по требованию

- `src/App.tsx`: `React.lazy` для каждого маршрута, `Suspense` с индикатором. При открытии сайта не загружать сразу PostEditor, Chat, HabitPage, Settings, WallpaperStudio, Admin и т. д.
- `src/components/modules/ModuleMap.ts`: каждый модуль `Blackout` импортируется динамически при первом открытии; экспортируемые по имени `PickHandler` и `BgHandler` адаптируются в `default`. Overlay и стек модалок остаются в `Blackout.tsx`, где `Suspense` выводит индикатор во время загрузки.
- Общие провайдеры, SideMenu, ContextMenu и жесты остаются синхронными во избежание задержки долгого удержания, переключения меню и потери состояния.
- В медиа ленты постов и сообщений: `loading=lazy`, `decoding=async`; у видео `preload=metadata`. Открытый просмотр, интерактивный редактор и текущее выбранное изображение не переводить автоматически на lazy.

## Проверка

1. После `npm run build` сравнивать **entry chunk** с baseline. Сумма всех динамических JS-файлов может не уменьшиться (из-за общих чанков), и она не равна первичной сетевой загрузке.
2. Проверять прямые переходы `/sign`, `/info/roadmap`, `/post/new`, `/wallpapers`, `/chat/:nick`, `/habit/:id` и переходы внутри приложения.
3. Все ключи `ModuleMap` и сценарии `Blackout` должны сохраниться; открытие, вложенные модалки, свайп закрытия и анимации требуют проверки с авторизованной QA-сессией.
4. Браузерный `tests/e2e/smoke.spec.ts` проверяет общедоступное. Авторизованные проверки без фикстур пропускаются — не считать это подтверждением чата и активности.
5. Обои, анимацию фоновых сцен и существующие изображения этим изменением не переделывать.

## Память при локальных предпросмотрах

В `AccPostMedia`, `CommentTAFiles`, `PickHandler` и `CreateChatInfo` временные `blob:`-ссылки создаются в `useEffect` только при изменении списка `File` или выбранного файла и освобождаются через `URL.revokeObjectURL` при смене/размонтировании. Никогда не вызывать `URL.createObjectURL` прямо в JSX / `.map` на каждом рендере: набираются невысвобожденные Blob-URL, а Cropper и preview перезагружаются. За образец также принять существующий `MediaDraft`.

После добавления/удаления вложений проверить превью изображений, видео, кадрирование, замену аватара и последующую загрузку файла. Сам объект `File` не изменён.

## Защита от регрессий размера

В `scripts/check-bundle.mjs` после Vite build проверяется реальный JS entry из `dist/index.html` и лимит **1,5 МБ без gzip**. Это бюджет на начальный чанк с запасом для изменений, а не обещание соответствующей фактической сетевой загрузки. Проверка запускается через `npm run check:bundle` в GitHub Actions и также выводит число JS-чанков. `src/scss/App.scss` напрямую подключает штатный `Loading.scss`, чтобы общий индикатор `Suspense` был оформлен даже при первом открытии /sign, до загрузки lazy-кода страниц.

## Постоянный layout и кэш

`ResponsiveLayout` и `MobileLayout` теперь импортируются синхронно. При ожидании содержимого lazy-страницы `Suspense` рисует штатный `Skeleton` **внутри** уже смонтированного layout. SideMenu, его header/nav и выбранный Background не размонтируются. В `Background` используются сохранённые локальные эффекты сразу, а не скрывается весь фон до ответа API.

Для экономии трафика работают локальные настройки `settings_auto_load_images` (загрузка изображений постов и чатов по нажатию), `settings_auto_play_gif` (GIF по нажатию, без preloading видео), `settings_use_image_cache` (опциональный кэш публичных встроенных обоев). Загружаемые пользователем файлы и история чатов в CacheStorage не помещаются.

Vercel: `/assets/*` — immutable, `/wallpapers/*` — ограниченный HTTP cache, `/index.html` — revalidation, `/api/*` — no-store. Service Worker `at-wallpaper-cache-sw.js` работает только с GET `/wallpapers/*`, сохраняет максимум 12 публичных изображений для офлайн-запасного варианта, выключение удаляет только его хранилище, но не снимает регистрацию — этот же SW нужен для Web Push. Стандартный HTTP-кэш браузера живёт по отдельным правилам.

Уведомления запрашивают системное разрешение только при нажатии пользователем. `denied` необходимо изменить вручную в браузере. Для уведомлений после закрытия сайта используется Web Push (Push API/VAPID), при условии активной серверной подписки. См. WEB_PUSH.md.

## Проверка загрузки и разрешений

`UserProvider` больше не вызывает `Notification.requestPermission` при входе; разрешение запрашивается только по прямому нажатию в настройках. Mobile Playwright smoke проверяет, что DOM-узлы `.background` и `.sideMenu` не размонтируются при переходе между вкладками Info. Это не заменяет визуальную проверку 1-кадрового мигания в Safari на iPhone.

- Модальные `Suspense` теперь показывают трёхстрочный штатный `Skeleton` внутри `Blackout`, на мобильном — нижний лист без разрыва фоновой сцены. Если CacheStorage недоступен или закончилась квота, встроенная картинка загружается как обычно: ошибка записи в кэш никогда не заменяет успешный ответ сети.

## Общие стили и ленивые маршруты

После перевода маршрутов и модалок на `React.lazy` общие селекторы `settingInnerDiv`, `settingSpan`, `settingInnerList`, `settingHint`, `settingSL`, `settingInnerButt`, `wtbgButt`, `moduleName`, `addHabitGoal` и `addHabitSave` не должны зависеть от открытия Settings, Landing, ShareAcc либо AddHabit. Их исходные правила вынесены в `src/scss/sharedControls.scss`, подключённый в `App.scss`; дубликаты удалены из CSS отдельных страниц. `SideMenu` содержит собственные гостевые стили входа и переключения темы, а действия блокировки и перехода в чат скрываются у неавторизованных пользователей. Подтверждение — прямые переходы на гостевой `/acc/bob`, `/info/roadmap` и проверки общих кнопок в `tests/e2e/smoke.spec.ts`.

## Стили форм активности

Поля `.addHabitWrapper` / `.addHabitInput`, выбор тега (`.tegSelector`, `.tag`, `.addTeg`, `.tagList`), время (`.addHabitTimeWrapper`), даты (`.AddHabitDateSpan`) и дни недели (`.dayChanger`) используются одновременно в модалке создания активности и в `HabitInfo` на `/habit/:habitId`. Правила вынесены из лениво загружаемого `addHabit.scss` в `src/scss/modules/habitFormControls.scss`, который импортируют **оба** маршрута через `addHabit.scss` и `redHabit.scss`. Страница редактирования не должна требовать предварительного открытия «Добавить активность» для правильного оформления. Браузерный тест с прямым переходом на `/habit` проверяет фон полей, теги, список и кнопки недели.

## Хедеры и порядок слоёв

`HabitName` больше не использует стили `.chatUserPick`, `.chatUserName` и `.chatOnlineStauts` из лениво загружаемого Chat: значок тега, название и строка серии оформляются в `HabitName.scss`. У общего `.headerDiv` задан `z-index: 6` без `!important`, а у `.habitMenu` — `7`; открытая панель активности должна быть выше хедера. У Wallpaper Studio остаётся отдельное правило для собственного заголовка. Браузерный smoke-тест на прямом `/habit` проверяет SVG, текст и этот порядок слоёв.
