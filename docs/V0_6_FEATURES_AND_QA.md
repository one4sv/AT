# dev 0.6.0 — роли, текстовые поля, возможности и QA

Инструкция AT. Читать совместно с [CODE_STYLE](CODE_STYLE.md), [CUSTOM_COMPONENTS](CUSTOM_COMPONENTS.md), [SCSS_GUIDE](SCSS_GUIDE.md) и [CONTINUE](CONTINUE.md). Проверять реальные права сервером, не полагаться на disabled в интерфейсе.

## Системная роль owner
- В каждой беседе только один владелец по `chats.creator_id`; `owner` — защищённая роль, приоритет **100**, 15/15 прав.
- Название, описание, приоритет и разрешения owner нельзя редактировать, понижать или отменять даже владельцу. Поля и переключатели только для просмотра.
- Owner нельзя назначить ролью по умолчанию или вручную присвоить другому участнику. Доступные другие ранги: 1–99.
- Защищать на сервере: `routes/chat/editpermissions.js`, выдачу в `getpermissions.js`, существующую проверку `creator_id`. UI `PermissionsSettings.tsx` должен скрывать owner в `SelectList` роли по умолчанию, показывать 15/15 и отключать его поля.
- Запрет проверять прямыми API-запросами: `default_role_id`, `rank`, `desc`, `role_name`, 15 ключей permissions, назначение owner, попытка назначить себе права. Не менять фактических владельцев.

## Все текстовые поля
- **Ни один `textarea` не должен иметь ручного `resize`**: `resize: none` глобально и локально. Не путать с автоматическим увеличением высоты.
- Текст должен расширять поле по содержимому, включая загруженное значение и вставку. `TA.tsx` уже измеряет scrollHeight и ограничивает min/max; `AutoDesc.tsx` увеличивает высоту. Для простых textarea применяется `field-sizing: content`; в браузерах без поддержки проверять необходимость JS fallback.
- Ограничение `max-height` и внутренний скролл при очень длинном тексте допустимы; запрещены видимые resize-ручки. К описанию роли использовать общий `TA`; для owner описание readonly.
- Проверить мобильную клавиатуру, длинный текст, переход между ролями, чаты, посты, комментарии, настройки и редактирование описаний.

## Возможности редактора
- `PostEditor.tsx`, `PostToolbar.tsx`, `PostMediaNode.tsx`: создание/редактирование постов, форматирование, медиа внутри текста, вложения, настройки видимости и привязка к активности.
- Не объявлять завершёнными непроверенные сценарии: редактирование в Safari, множество файлов, сохранение keptMedia, сетевые ошибки, предотвращение дублей. Дальнейшие задачи — Linear.

## Совместные активности
- Приглашение участника, принятие/отказ, подключение к беседе, управление участниками и настройками доступа.
- Выполнение `personal` («У каждого своё») и `shared` («Общее для всех»), отдельные настройки прогресса таймера/счётчика/задач и блоков расписания. Личные выполнения пользователей не смешивать.
- Сервер обязан проверять `can_complete`, `can_comment`, `edit_blocks`, `edit_info`, `invite`, права беседы, блокировки. Проверить комментарии с авторами, календарь, статистику, расписание и realtime.
- **E2E в беседе обязательно:** создать QA-беседу и активность, выбрать 2 режима выполнения, назначить роли, переключить 15 разрешений; проверить выполнение, таймер, счётчик, задачи, комментарии и статистику от владельца, принятого участника, постороннего и заблокированного. Проверить смену ролей, исключение, повторное приглашение и запрет обхода через API. Использовать только тестовые записи, не трогать реальные данные привычки 19.
- Мобильный iPhone Safari + ПК: SelectList, переполнение, скролл, свайп, длинное описание, отсутствие дублирующей кнопки «Отмена»/крестика в модалке прав.

## Стиль и документы
- Внутренние радиусы 24px; `SelectList` для выбора ролей; раскрытый popup — `var(--bgc)` (в glass `--mc` прозрачен). Стили SCSS многострочные с отступами 4 пробела, `vw/dvh` для геометрии.
- **Не вводить `font-weight`.** Переиспользовать существующие TA, SelectList, RadioGroup, Blackout.
- В разделе информации версия `dev 0.6.0`. FAQ обновляется синхронно в `src/i18n/locales/ru/info.json` и `en/info.json`: editor, совместки, выполнение, роли, owner, QR-приглашения, комментарии, дорожная карта. Не обещать ещё не выпущенные функции.
